# 动手对比结果：conductor 当执行器（2026-11-14）

> **后来的变化（同一天）**：本文的结论"用 conductor 当执行器"已被推翻。用户要求画布页面必须能拖、能点、能在节点上操作之后，流程图、人工验收、断点续跑都由我们自己的页面和文件接管，conductor 只剩分流和步数上限两样用得上，用户选了"改成自己写"。现在的执行器是 `app/engine.py`，约定见 `docs/05-产线文件与接口.md`。conductor 留在电脑上没卸。
>
> 本文留着的价值：三条判定线的实测方法、真模型试跑学到的两条经验（只有真模型试跑才看得出站的毛病；退回理由要写成能照着做的指令）、本机环境的几个坑。

## 一句话

三条判定线都过了，定下来走甲：**Claude Code 设计，conductor 当执行器**。有一处没测到：真模型单次调用最长只测到 38 秒，"跑几分钟"只用空等 150 秒验证过。

（第三条最初没测成，因为命令行版 Claude Code 登录过期；用户重新登录后当天补测。Codex 的默认模型配错，"换别家工人"仍没测。）

## 测了什么

装的是 microsoft/conductor v0.1.45（2026-11-10 发版）。样线在 `trials/toy-summary/`：一篇文章进、一段摘要出。

- 三站：提要点、写摘要、收尾。
- 两道门：机器门（查字数 60 到 120、只有一段、没有开场白），人判门（验收）。
- 两条退回路：机器门不合格退回"写摘要"；人判不合格也退回"写摘要"，并带上理由。
- 上限："写摘要"最多做 3 次，超过就停线。

每站的工人只拿到半成品文件和本站规格。测试分两轮：先用"假工人"（固定输出的替身程序，第一次故意把摘要写得太短，好触发退回）测执行器；登录修好后用真模型（`claude -p`，最便宜的 haiku）补测。

## 三条判定线

| 判定线 | 结果 | 实测到的事 |
|---|---|---|
| ① 半成品落在固定位置的文件；停掉后能接着跑 | 通过，有保留 | 每件活一个文件夹，半成品和状态文件都在里面。在等人验收时停掉运行，再恢复，接着停在人判门，表态后走到出货 |
| ② 不合格退回指定站；超上限是停下，不是放行 | 通过 | 机器门不合格退回重写后通过；强制"永远不合格"时第 3 次停线，命令返回失败；执行器自己的步数上限撞线时也是报错停下 |
| ③ 调 `claude -p` 跑几分钟的一站连续几次都稳 | 通过，有保留 | 真模型共 35 次调用全部成功，其中长任务 3 次（每次 33 到 38 秒，产出四五千字）。一站空等 150 秒，执行器没有误杀。保留：没有压出真正"几分钟"的真模型调用 |

第 ① 条的保留：

- 恢复靠的是 conductor 自己的存档文件，在系统临时目录（`%TEMP%\conductor\checkpoints\`）里，不是我们的状态文件。临时目录被清掉就恢复不了。
- 执行器自己停下时（撞步数上限、某站超时、被手动停止），我们的状态文件不会更新，停留在上一步的状态。需要外面再包一层，在执行器退出时补记一笔。这层还没写。

## 真模型补测：门拦住了次品，改站之后出货

| 轮次 | 结果 |
|---|---|
| 原规格连跑 5 次 | 20 次调用全部成功。5 件**全部停在机器门**：规格要求 60 到 120 字，模型每次写 140 到 180 字，退回两次仍超，第 3 次停线 |
| 改站不改门，再连跑 5 次 | 5 件全部出货。4 件一遍过；1 件写了 123 字被退回，拿到理由后改成 97 字通过 |
| 长任务连跑 3 次 | 全部成功，每次 33 到 38 秒 |

第一轮全部停线不是执行器的毛病，是"写摘要"这一站设计得不好：

- 模型不擅长数字数。
- 退回理由只说"现在是 166 字"，它不知道该怎么改。

改了两处，门的标准没动：

- 规格里加"最多 3 句话、目标 90 字、宁短勿长"。
- 退回理由改成能照着做的："超出 46 字，请删掉次要细节，压到 3 句话以内，大约是现在篇幅的 54%"。

这一轮得到两条对以后设计每条线都有用的经验：

1. **只有真模型试跑才看得出站的毛病。** 假工人测得出执行器对不对，测不出规格写得好不好。所以"AI 设计完自己验证跑通"必须包含拿样例原料用真模型跑几遍。
2. **退回理由要写成能照着做的指令。** 只报"哪里不合格"不够，要说"怎么改"。

## 流程图

`conductor run` 加 `--web` 会开一个本机网页，显示实时流程图：走过的站和连线变绿，等人的站单独标出，退回的回头线画成虚线，下方是逐步日志。图可以缩放、拖动查看。

- 一次运行对应一件活。多件活同时在线上，要开多个网页或用它的 `fleet` 命令，这个没测。
- 改流程要改 YAML 文本，图上不能用鼠标改。
- 点节点会在右侧弹出面板：普通站显示状态、耗时、返回码、输出；人判门显示验收提示和"合格 / 不合格"两个选项。
- 人判门可以在网页上点，也可以用命令表态。我只测了命令方式，网页上的选项看到了但没点。
- 这张图只在一次运行期间存在（或事后回放），不运行时没法打开一条线来看和改。
- 它是用 React Flow 做的。节点在代码里标了可拖动；我试拖了一次，结果把整张图拖出了视野，没能确认单个节点能不能挪位置。

用户已定（2026-11-14）：改图必须支持鼠标拖，点节点要显示信息和操作。自带的图满足不了，要另做一块我们自己的画布页面，见 `docs/01-需求.md` 需求 8。

## 胶水代码有多少

- `tools/line_tools.py`：164 行 Python。做三件事：把半成品和规格交给命令行工人并把产出写成文件、机器门、记状态。
- `line.yaml`：144 行，是流程定义。

对比"自己写执行器"估计的 500 到 900 行，分流、人判门、流程图、存档恢复、步数上限这五样不用自己写。

## 碰到的毛刺

1. **`--skip-gates` 会自动选人判门的第一个选项。** 我们的第一个选项是"合格"，带这个参数跑等于跳过人工验收。约定：正式投料不许带它；或者把"不合格"排在第一个。
2. **某站超时不走流程里画的"停线"路由。** 执行器直接报错并存档。是停下不是放行，但我们的状态文件记不到。胶水代码里自己设了超时来兜住。
3. **"停止"命令报告没停成，实际停了。** 之后查状态显示已结束，存档也在。
4. **安装时 git 取代码失败。** 原因不在 conductor：本机全局 git 配置里 `http.postBuffer` 设成了 50 GB，git 按这个数申请内存失败。安装时临时覆盖成 1 MB 绕过，没有改全局配置。

中文没出问题：中文的退回理由经命令行传进去、写进状态文件，都是原样。

## 没测到的事

- **换别家工人。** Codex 报默认模型 `gpt-6.1-sol` 不支持用 ChatGPT 账号登录的方式，一次都没跑通。
- **真正跑几分钟的真模型调用。** 最长只到 38 秒。
- **真模型下的人判门。** 补测时人判门用了自动通过，只为测稳定性；人判退回只用假工人测过。
- **工人需要动本机文件或跑命令的站。** 样线里工人只收文字、吐文字，不给任何工具，所以没碰到权限放行的问题。真线上遇到这种站，要逐站列明允许它做什么。
- 网页上点人判门、多件活同时在线、节点名用中文。
- "AI 只拿到两头，自己把线设计出来"。这次的线是我照着 conductor 的说明写的，第一次检查就通过，但这只是一条玩具线。

## 结论

**走甲：Claude Code 设计，conductor 当执行器。** 三条判定线实测通过，胶水只要一百多行，没有出现要改走"自己写执行器"的情况。

什么时候回头重审这个选择：conductor 停止维护；或者真线上碰到它绕不过去的限制（比如多件活同时在线管不过来）。到那时我们的半成品、状态文件、站规格、门都是独立的文件，换执行器只需重写流程定义那一份。

## 需要你做的

1. **（可选）修 Codex 的默认模型。** 它的配置里默认模型是 `gpt-6.1-sol`，换成你的 ChatGPT 账号支持的模型。不修的话"换别家工人"这条测不了。
2. **（可选）看一下全局 git 配置里的 `http.postBuffer`。** 50 GB 这个值会让别的工具通过 git 取代码时也失败。

## 装了什么，怎么卸

- 装了：conductor v0.1.45，位置 `C:\Users\chang\.local\bin\conductor.exe`，由 uv 管理。
- 它在磁盘上留的东西：`%TEMP%\conductor\`（事件日志和存档）、`%USERPROFILE%\.conductor\runs\`（运行记录）。
- 卸载：`uv tool uninstall conductor-cli`，再删上面两个目录。
- 样线：`trials/toy-summary/`，对比做完后可以整个删掉。
