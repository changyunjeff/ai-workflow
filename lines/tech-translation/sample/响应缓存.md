# Configuring the response cache

The gateway can cache upstream responses to reduce load on your backend services. Caching is disabled by default. To enable it, set `cache.enabled` to `true` in `gateway.yaml` and restart the gateway with `gatewayctl restart`.

Each cached entry has a time-to-live (TTL). When the TTL expires, the entry becomes stale but is not removed immediately. If `cache.serve_stale` is enabled, the gateway returns the stale entry to the client while it revalidates the entry against the upstream in the background. This keeps latency low during traffic spikes, at the cost of occasionally serving data that is a few seconds out of date.

The cache key is built from the request method, the full URL, and the headers listed in `cache.vary_headers`. Do not add the `Authorization` header to this list unless every user should have a separate cache; doing so sharply lowers the hit rate and increases memory usage.

To purge a single entry, run `gatewayctl cache purge --url <URL>`. To purge everything, run `gatewayctl cache purge --all`. Purging everything on a busy gateway causes a burst of upstream requests, so prefer purging by URL prefix where possible.
