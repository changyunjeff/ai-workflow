# 同行调研结论（2026-11-14）

本文是调研的定稿结论，以它为准。完整报告在 `reports/AI 工作流工具同行调研.md`，但那份报告的结论被盲审推翻了一半，读它之前先看本文"盲审改掉了什么"一节。

## 一句话

n8n 的四条限制大体属实；查过的现成工具里没有一个拿来就满足八条需求；但"发动机（逐站跑流程的那个程序）要不要自己写"**还没定**，差一次动手对比。

## 怎么查的

四个代理各扮一个行当的专家分头查，一个代理汇总成报告，一个全新的代理只看报告挑刺，最后我自己打开原文复核了两处争议。

**全部结论来自读公开文档，没有安装或运行过任何一个工具。**

## 问题一：n8n 的四条限制是否属实

n8n 正在换代：3.0 版 2026-10-27 发布测试版，官方说稳定版 12 月初。

| 原来的说法 | 结论 | 依据 |
|---|---|---|
| ① 碰本机的程序和文件别扭 | 属实，3.0 起更严 | 跑本机命令的节点在云版没有，自装版从 2.0 起默认关闭；3.0 起自装只支持 Docker（把程序关在隔离容器里跑），命令在容器里执行 |
| ② 运行状态在它自己的数据库里 | 运行状态属实；流程定义只对一半 | 运行记录在数据库，默认 14 天清理；流程定义可以导出成文本文件 |
| ③ AI 只是节点，没有"验收、退回" | 前半句已过时；后半句对一半 | n8n 现在有对话助手能建、跑、查错、修；官方还开了接口让 Claude Code 直接搭和试跑。"退回"可以用条件判断接回前面的节点画出来，但没有"门"这个概念 |
| ④ 要养常驻服务 | 属实，3.0 后门槛更高 | 3.0 不再支持原来较轻的安装方式，在 Windows 上等于常开 Docker Desktop |

盲审者抽查了这四条的官方页面，全部一致。

"3.0 的容器碰不到 Windows 上的 `claude`"是推断，没有实测。

## 问题二：现成工具里有没有已经满足的

**查过的里面没有一个拿来就能用。** 这是"没找到"，不是"世上没有"：Node-RED、微软 Power Automate 桌面版没有查，多处判定依据的是"文档没提"。

各类工具缺什么：

- **对话式搭流程平台**（Dify、Langflow、Sim、Zapier、Make 等）：运行状态都在数据库或厂商的云里，没有把"跑本机命令"当正经一站的。清单里两个已停：OpenAI Agent Builder 2026-11-30 关停，Flowise 2026-08 归档。
- **Claude Code 自带的工作流脚本**：能设计、能反复跑，但运行中不能停下来等人验收、干活的只能是 Claude、没有流程形状图。
- **老牌文件式流水线**（Snakemake、DVC 等）：状态就是文件、定义是文本、能空跑检查，但规定流程不许回头，只能原地重试。
- **编排引擎**（Kestra、LangGraph 等）：能回头、能等人，但状态在自己的库里，或要养常驻服务。

"写明这条线什么时候拆"在所有读到的文档里都没有对应概念，这条只能靠我们自己的约定。

最接近的四个：

| 工具 | 已有 | 缺或不明 |
|---|---|---|
| microsoft/conductor | 定义是文本文件；能跑本机命令并按结果分流；人工验收可在网页上点；带上限的回头循环；不真跑的检查命令；实时流程图；Windows 安装脚本；附带教 Claude Code 写定义文件的技能包；MIT 许可 | 项目小（502 星），版本号还在 0.1.x；图能拖动查看，改流程仍是改文本。运行状态存在哪已实测，见 `docs/03-动手对比结果.md` |
| Archon | 有门、循环到通过为止、人工审批、支持 Claude Code 和 Codex | 运行状态在数据库（SQLite） |
| babysitter | 门强制执行、状态是文件、可续跑 | 没有流程图；说明文档没提 Windows |
| Claude Code 工作流脚本 | 官方自带、零安装 | 见上 |

## 盲审改掉了什么

报告原来的结论是"以 Claude Code 为底座，发动机自己写"。盲审者只信五成，理由成立：

1. **漏了一个更省事的选项。** 报告淘汰 conductor 和 Archon 的理由是"线要人手写"，但我们的方案里线本来就是 Claude Code 写的。"Claude Code 当设计者 + 现成发动机"这个组合没被评估。
2. **conductor 的一条事实写错了。** 报告说它"不能用命令行工具当工人"，它的说明文档明写可以跑任意本机命令。我复核了原文，盲审者是对的。
3. **没用同一把尺子量自己。** 报告给别人打分时"改文本文件"算"图不能手改"，而自己的方案改图也是改文本文件。
4. **"薄层"把工作量说小了。** 定义文件、状态文件、运行程序、出图，四样加起来就是整个系统。

## 现在的结论

排除 n8n 和对话式平台：它们缺的是结构（文件式半成品、门、不养数据库），装插件补不上。

剩两条路，设计者都是 Claude Code，区别在发动机：

- **甲：用 conductor 当发动机。** 好处是门、退回、人工验收、流程图都现成，不用维护自己的程序。风险是项目小、版本号还在 0.1.x。（更正：它有正式发版，最新 v0.1.45，2026-11-10。）
- **乙：自己写一个小发动机。** 好处是完全按设计标准来，状态天然是文件。代价是估计 500 到 900 行 Python（没有原型佐证），以后坏了只能靠 AI 修。

**我的判断：先试甲，限半天。** 下面三条有一条不过就改走乙：

1. 站与站之间的半成品能放在固定位置的文件里，中途停掉后能从文件接着跑。
2. 门不合格能退回指定的站；超过次数上限是停下来报告，不是放行。
3. 在这台 Windows 上调 `claude -p` 跑几分钟的一站，连续几次都稳。

**动手对比已做（2026-11-14）：三条都通过，定下走甲。** 详见 `docs/03-动手对比结果.md`。

两条路都**不满足**"用鼠标拖着改图"：改图的方式是提意见让 AI 改，或者改文本文件。

## 三个风险

1. **可能要多花钱。** 现在 `claude -p`（不开对话框、一条命令调 Claude Code）用的是订阅登录。官方文档写明"精简模式"将来会成为它的默认，而精简模式不读订阅登录，要另配按量付费的密钥。到时能不能关掉精简模式，文档没说。
2. **无人值守的代理能在这台电脑上写文件、跑命令。** 新版 `claude -p` 默认拒绝没预先放行的操作，所以每一站都要列明允许它做什么。这是保险，设计时要用上。
3. **两条路都要靠 AI 维护。** 甲依赖一个小项目，乙依赖自己写的程序，你都没法自己修。

## 需要你定的三件事

1. **允不允许在这台电脑上安装 conductor 做对比。** 要下载并运行微软仓库的安装脚本，它会顺带装 uv（一个 Python 工具管理器）。对比会消耗订阅额度，量没测过。
2. **拿哪条线做样线。** 按铁律第 5 条，应该是你手工做成过两次、成品认可过的。没有的话我用一条玩具线（比如"一篇文章进，一段摘要出"），那样只能测发动机，测不了 AI 设计得好不好。
3. **改图方式能不能接受。** 如果一定要鼠标拖着改，要另加一个画布编辑器，工作量和选型都要重算。

## 还没查实的事

- conductor、Archon、babysitter 在这台 Windows 上能不能装、能不能跑。
- conductor 的运行状态存在哪、流程图上能不能看到每件活在哪一站。
- Codex、Gemini 等别家命令行工具在 Windows 上当工人是否稳定。
- "AI 只拿到两头，第一次就把线跑通"的比例，没有任何数据。
- n8n 对话助手的预览开关在 2026-11 是否还在。
