# 对话式搭流程平台(可视化 LLM 流程搭建器 + "说一句话就给你搭好流程"的产品)

> 读法说明。所有页面的查阅日期都是 2026-11-14。每条事实后面带三种标记之一:
> **【一手】** = 我读到了官方文档、官方更新日志、官方仓库或官方定价页;**【二手】** = 来自第三方文章、目录站或搜索摘要,没读到官方原文;**【未核实】** = 没找到可靠来源,不当事实用。
> 术语先定义:**节点/站** = 流程图上的一个方块,做一件事;**画布** = 能拖方块连线的图形界面;**MCP** = 一种让外部 AI(比如 Claude Code)调用某个软件功能的标准接口;**HITL**(human-in-the-loop)= 流程跑到一半停下来等人点头;**沙箱** = 一个隔离的小环境,代码在里面跑,碰不到你电脑上的东西;**自托管** = 把软件装在自己机器上而不是用厂商的云;**BYOK** = 自带大模型密钥,模型费直接付给模型厂商;**常驻服务** = 要一直开着、要升级、要备份的后台程序。
> 覆盖的产品:Dify、Flowise、Langflow、OpenAI Agent Builder(AgentKit)、Zapier(Copilot / Agents / MCP)、Make(Maia)、Gumloop(Gummie)、Lindy、Sim(sim.ai)、Activepieces,另加我认为值得看的 n8n Assistant 和 Google Opal。ComfyUI 的 Comfy Agent 只做图像生成流程,不算通用,只在问题一提一句。

## 问题一:有没有"用大白话让它替我搭流程"的功能?产出什么、在哪个套餐、会不会自己试跑并修错,还是只画一张草图?

### Takeaway
到 2026 年 11 月,几乎每家都有"说一句话生成流程"的功能,但**官方文档明确写出"自己搭、自己跑、自己找错、自己修、再跑"这个闭环的只有 n8n Assistant**(2026-09 发布,仍是预览);Sim 的 Chat 写的是"能建、能测、能调试",但措辞是"提出修改 + 给出验证结果,由你检查";其余(Dify、Langflow、Zapier、Make、Activepieces、Gumloop、Flowise)的内置助手,官方文档都没说会自己试跑修错,其中 Zapier 明说要用户自己点测试。另外两件大事:**OpenAI Agent Builder 定于 2026-11-30 关停,Flowise 已在 2026-08 停止维护并归档**。

### Inferences
- "会画"已经是标配,"会自己验证"才是分水岭。按官方文字的强弱排:n8n Assistant(明说自动循环)> Sim Chat(能测能修,但要你看验证结果)> Make Maia(能看日志修错,没说自己跑)> Dify/Langflow/Activepieces 内置助手(只生成)> Zapier Copilot(明说你自己测)。
- Dify、Langflow、Activepieces、Sim 都另开了一条"让外部编码代理来搭和测"的路(见问题三)。走这条路时,"自验证"靠的是 Claude Code 自己调它们的测试/运行接口,而不是产品内置助手。这正好对上需求 1 和需求 3,但闭环逻辑得自己写在 Claude Code 这一侧。
- 2026 年两个可视化搭建器退场(OpenAI Agent Builder、Flowise),Flowise 给的理由直接是"编码代理把低代码流程的活抢了"。这对"自己造"是个信号:画布作为**主要搭建手段**在失势;但用户要的是画布作为**审阅手段**,两者不矛盾。

## 问题二:某一站能不能在用户自己的 Windows 电脑上跑命令行程序(尤其是 `claude -p`、`codex exec` 这类命令行编码代理)并读写本地文件?还是只能在云上或沙箱里?

### Takeaway
**没有一家把"在用户 Windows 本机跑一个命令行程序、读写本地文件夹"当成正经的一站来支持。**纯云产品(Zapier、Make、Gumloop、Lindy、OpenAI、Opal)做不到;自托管的 Dify、Sim、Activepieces 把代码关在 Linux 沙箱或容器里;只有 Langflow 能原生装在 Windows 上(桌面版或 pip),理论上可以用自定义 Python 组件去调本机程序,但这是我的推断,官方没有现成的"运行命令"站。

### Cited Findings
- 【一手】**Langflow**:README 写 Langflow Desktop "支持 Windows 和 macOS",自带依赖、不用管 Python 环境;也可以 `uv pip install langflow -U`(Python 3.10–3.14)。1.10 博客确认 Windows 上支持 Python 3.10 到 3.14。自定义组件功能受开关 `LANGFLOW_ALLOW_CUSTOM_COMPONENTS` 控制。— [Langflow README](https://github.com/langflow-ai/langflow)、[Langflow 1.10](https://langflow.org/blog/langflow-1-10)、[Langflow Assistant 文档](https://docs.langflow.org/langflow-assistant)
- 【一手】**Dify**:自托管要 Docker 和 Docker Compose(v2.35.0 以上),最低 2 核 CPU、4 GiB 内存。Agent 应用(2026-07 起公测)"跑在 Linux 沙箱里","内置沙箱用于执行代码和 shell 命令";v1.16.1 起本地沙箱被放在 Squid 转发代理后面;v1.17.0 可换成 E2B 云沙箱。也就是说命令能跑,但是在隔离的 Linux 环境里,不是你的 Windows 桌面。— [Dify README](https://github.com/langgenius/dify)、[Dify releases](https://github.com/langgenius/dify/releases)

## 问题三:流程定义存在哪(能不能导出成文件、什么格式、适不适合放进 git)?运行状态存在哪(数据库还是文件)?外部代理(如 Claude Code)能不能通过 API、命令行或 MCP 新建、修改、运行流程?

### Takeaway
**"让 Claude Code 从外面建、改、测、跑流程"在 2026 年已经是四家开源产品的官方功能**:Langflow(lfx-mcp)、Sim(MCP + 命令行 + 技能包)、Activepieces(MCP)、Dify(difyctl + 技能)。但**运行状态无一例外放在产品自己的数据库或厂商云里**,没有一家把"每站的半成品 = 固定位置的带状态文件"当成模型。流程定义多数能导出成 JSON 或 YAML 文件。

## 问题四:退回前面某一步、质量门、评估器、人工审批,是不是一等公民?

### Takeaway
"人工审批"已是标配(Dify、Flowise、Sim、OpenAI、Zapier 都有专门的站),"循环"也普遍有,但**多数产品的循环是"容器"(把几个方块框起来重复跑),不是"不合格就退回到指定的上游站"**。唯一把"退回到先前某个节点"做成一个站的是已停更的 Flowise(Loop 节点的 "Loop Back To")。"带合格标准的验收门"没有任何一家当成一等概念;最接近的零件是 Sim 的 Evaluator(按指标打分)和 Guardrails,以及 OpenAI 的 Guardrails。

### Cited Findings
- 【一手】**Flowise**:Loop 节点"明确地把执行重定向回先前执行过的某个节点",两个设置:"Loop Back To"(退回到哪个节点)和 "Max Loop Count"(每次运行最多退回几次,默认 5,防死循环)。Human Input 节点暂停流程、给出两个动作各走一条出线、可附带反馈文字。Condition 按规则分支,Condition Agent 让大模型在几种情形里选一条路。— [AgentFlow V2 文档](https://docs.flowiseai.com/using-flowise/agentflowv2)
- 【一手】Flowise 官方教程的例子正是"人工拒绝 → 进 Loop 节点 → 带着反馈退回到 Agent 重做"。— [Human in the loop 教程](https://docs.flowiseai.com/tutorials/human-in-the-loop)
- 【一手】**Sim**:Evaluator 方块"用模型按命名的指标给文本打分";Router"按你写的描述选一条路";Condition 用 JavaScript 布尔表达式分支;Guardrails 校验 JSON、匹配模式、查依据、识别个人信息;Loop 是**容器**,四种模式(for、forEach、while、do-while),while 类最多 10,000 轮,超了整次运行报错。Loop 文档没说能不能在容器外画一条回到上游的线,也没说 Evaluator 的分数怎么接到循环条件上。— [文档索引](https://docs.sim.ai/llms.txt)、[Loop block](https://docs.sim.ai/workflows/blocks/loop)

- 【一手】**Langflow**:lfx-mcp 的 `validate_flow` 只检查连线对不对,不是质量门;我读到的 Assistant 和 MCP 文档都没提人工审批或退回。— [lfx-mcp 文档](https://docs.langflow.org/lfx-mcp)
- 【一手】**n8n Assistant** 自己有"停下来等人"的规矩(凭证访问和启用流程要你确认),但这是搭建过程的门,不是流程里的门。— [Introducing n8n Assistant](https://blog.n8n.io/introducing-n8n-assistant)

### Inferences
- 用户的设计标准有四个要素:①每站的输入输出是带状态的文件;②每站一道门(格式、谁判、合格标准);③不合格退回**指名的**上游站;④写明拆线条件。对照下来:②③只有 Flowise 的"Human Input/Condition → Loop Back To + 最大次数"在形状上接近;Sim 和 Dify 要靠"循环容器 + 条件 + 评分/审批"自己拼;①④**没有任何产品涉及**("拆线条件"这个概念我在任何一家文档里都没见到)。
- "循环是容器"和"退回是一条回边"在图上长得不一样:容器把几个站框起来重复,用户看到的是一个大框;回边是从门直接指回某一站的箭头,更贴近"退货"的直觉。用户要审的是后者。
- 机器判的门(格式校验、评分)和人判的门(审批)在这些产品里是两类不相干的节点,没有统一成"门"这一种东西,因此也没有"能让机器判的不让人判、人判的门尽量靠前"这类设计约束的落脚点。

### Gaps
- Sim 能否在循环容器之外连一条回到上游方块的线、Evaluator 的分数能否直接当 while 条件:文档没写。
- Dify 的 Loop 节点细节(退出条件、最大次数)和是否允许回边:本轮没读专页。
- Langflow 是否有循环组件和人工审批组件(2026 年版本):没核实。
- Activepieces 是否仍有"等待审批"的运行时组件:文档索引里没找到。
- Make 的人工审批、循环(迭代器/重复器)、错误处理分支现状:本轮没查。
- Lindy 现行产品里是否还有条件、循环、确认步骤:官方文档无条目。

- 需求 2("只给两头")我一律判"部分":各家助手都接受一句目标,但官方指引普遍建议把触发条件、步骤、要接的服务说清楚(例如 Sim 让你描述"触发、输入、步骤、集成、输出"),说明"只给两头"时产出质量没有保证。这是产品成熟度问题,不是功能有无问题。
- 需求 1 没有任何产品原生满足:它们的对话框后面是厂商自己接的大模型,不是可替换的命令行代理。能做到的是反过来——**把 Claude Code 当对话框,把这些产品当"画布 + 运行器"**。此时"换成 Codex CLI 或 Gemini CLI"取决于那个 CLI 支不支持 MCP 或能不能调命令行,和产品无关。
- 需求 5(b)(c) 是结构性缺口,不是哪家"还没做":这些产品的数据模型就是"节点之间传变量、执行记录进数据库",和"站与站之间交接文件、每站有门"是两种骨架。

### Gaps
- 表里的"?"都是真没查到,不是"大概没有"。尤其 Lindy、Gumloop 两行,因为产品在 2026 年改了定位,旧评测不可用,新文档又不覆盖流程编辑器。
- 我没有实际注册或安装任何产品(任务约束),所有判定都基于公开文档;"助手到底多可靠"这类体验性结论只有零星二手评价,不足以下定论。

## 问题七:总体——哪个最接近?最大的剩余缺口是什么?

### Takeaway
**按"产品整体最像用户要的东西"看,最接近的是 Sim;按"能在自己的 Windows 上、让 Claude Code 当大脑"看,最接近的是 Langflow。但两者都跨不过同一个缺口:没有"站 = 带状态的文件、每站一道门、不合格退回指名的上游站、写明拆线条件"这套骨架,运行状态都在数据库里;而且一个要常驻 Docker 服务且碰不到本机(Sim),一个没有验收门和自验证闭环(Langflow)。**现成产品里没有可以直接拿来用的。

### Cited Findings
- 【一手】Sim 同时具备:对话式搭建并能测试调试([Chat](https://docs.sim.ai/chat))、面向代理的"干跑—lint—测试—部署"接口、MCP、命令行和技能包([API](https://docs.sim.ai/api-reference/build-and-run-workflows))、评分和人工审批方块([文档索引](https://docs.sim.ai/llms.txt))、Apache 2.0([README](https://github.com/simstudioai/sim))。缺口:Shell 只在远程沙箱([Function](https://docs.sim.ai/workflows/blocks/function))、本机终端能力仅 macOS 桌面版且仅限 Chat([Desktop](https://docs.sim.ai/desktop))、自托管是 5 个常驻服务加 PostgreSQL([Docker](https://docs.sim.ai/platform/self-hosting/docker))。
- 【一手】Langflow 同时具备:MIT、Windows 桌面版([README](https://github.com/langflow-ai/langflow))、官方点名支持 Claude Code 的 MCP 桥,可用一段文字规格建整条流程、校验连线、运行([lfx-mcp](https://docs.langflow.org/lfx-mcp))、内置助手可建可改整条流程([Assistant 文档](https://docs.langflow.org/langflow-assistant))。缺口:助手不替你跑也不自动修错(同上);未见审批、退回、验收门。
- 【一手】n8n Assistant 是唯一官方明说"自己搭、自己跑、自己修"的,但它就是 n8n,需求 5 列的那些限制原样存在,且自托管只支持 Docker、仍是预览。— [n8n 博客](https://blog.n8n.io/introducing-n8n-assistant)
- 【一手】两个"可视化搭 LLM 流程"的代表在 2026 年退场:OpenAI Agent Builder(2026-11-30 关停)和 Flowise(2026-08-31 生命周期结束),Flowise 明说原因是编码代理兴起、低代码流程碰到复杂度天花板。— [OpenAI deprecations](https://developers.openai.com/api/docs/deprecations)、[Flowise sunset](https://flowiseai.com/sunset)
- 【一手】Dify、Langflow、Sim、Activepieces 四家在 2026 年都发布了"让编码代理从外部搭流程"的官方通道。— [Dify CLI](https://docs.dify.ai/en/cli/build-apps)、[lfx-mcp](https://docs.langflow.org/lfx-mcp)、[Sim API](https://docs.sim.ai/api-reference/build-and-run-workflows)、[Activepieces MCP](https://www.activepieces.com/docs/mcp/overview)

### Inferences
- **行业方向和用户的想法是同向的**:厂商自己也承认"大脑"应该是编码代理,画布退为"给人看、给人改"的界面。区别在于厂商保留了自己的运行器和数据库,而用户要的是文件和本机程序。
- **"用现成的"最省事的组合**是 Claude Code + Langflow 桌面版(经 lfx-mcp):免费、本机、有图、可手改。但要自己补:验收门与退回的表达方式、文件化的半成品、自验证闭环的逻辑、以及在 Langflow 里包一个调本机命令行的自定义组件(这一步可行性是我的推断,需要动手验证)。补完这些,Langflow 实际只剩"画图和手改"这一个用处。
- **"自己造"时值得抄的零件**(都有一手来源):Langflow 的"紧凑文字规格 → 一次生成整张图";Sim 的"先干跑预览 → lint → 应用 → 测试草稿 → 才部署,且草稿和已部署版本分开";Flowise 的"退回到指定节点 + 最大退回次数";n8n Assistant 的"自动循环只在需求有歧义和有后果的动作前停下";Dify 的"代理把工作存在固定文件夹、只有你说可以才发布"。
- **最大的剩余缺口,一句话**:所有产品都把流程理解成"一串往下走的步骤 + 存在数据库里的执行记录",没有一家把流程理解成"一条有质检、会退货、半成品摆在货架上(文件)的产线";而这恰恰是用户设计标准的核心。这个缺口不是加个插件能补的。
- 一个需要警惕的反面证据:Chat2Workflow 基准(二手)显示模型直接生成可视化流程定义时,复杂任务下正确率和稳定性都不好。这支持"AI 必须自己试跑验证"(需求 3)是必需项而不是加分项,也提示自造时流程定义格式要尽量简单。— [arXiv 2604.19667](https://arxiv.org/html/2604.19667v2)

### Gaps
- 我没有动手试任何一家(约束所限),所以"Sim 的 Chat 实际能独立修好多少错""Langflow Assistant 生成的流程一次能跑通的比例"这类决定性的体验数据是空白;只有 Activepieces 有零星"偶尔不靠谱"的二手评价。
- 没有找到任何一家主打"验收门 + 退回 + 文件化半成品"的对话式搭流程产品。我搜过的方向是通用自动化和 LLM 流程搭建器;如果这类产品存在,更可能出现在"编码代理的编排框架"那一类(不在本题范围,应由负责相邻题目的调研覆盖)。
- Relay.app、MindStudio、Vellum、Refly 等同类产品本轮搜索没有返回可用的一手材料,未纳入;不代表它们没有相关功能。
- Langflow 自定义组件在 Windows 桌面版里调用本机命令行程序是否顺畅,是"用现成的"这条路成立与否的关键,目前只是推断,建议用半小时动手验证后再做决定。
