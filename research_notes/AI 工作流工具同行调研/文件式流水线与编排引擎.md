# 文件式流水线与编排引擎（能不能直接拿来当"个人产线"的发动机或流程图）

> 调研日：2026-11-14。所有"最新版本/日期"都是这一天读到的，之后会变。
> 标注约定：**【一手】**= 本次亲自读了官方文档或官方仓库页面；**【二手】**= 来自论坛、博客、搜索摘要，没在官方页面核对；**【未核实】**= 本次没找到出处，只是提醒有这个问题，不能当事实用。
> 术语先说清：
> - **DAG**（有向无环图）：一张只能往前走、不能绕回头的流程图。很多工具强制要求流程是 DAG，也就是"不许退回上一站"。
> - **门**：一站干完后的验收检查，过了才放行。
> - **退回**：门没过，把活送回前面指定的某一站重做。在图上是一条往回指的箭头，所以图里有环。
> - **常驻服务**：要一直开着的后台程序（带数据库、要升级、要备份）。
> - **检查点（checkpoint）**：引擎把"跑到哪了"存下来，之后能接着跑。
> - **干跑（dry-run）**：不真干活，只打印"将会做什么"，用来在给人看之前自检。

## 1. 能否在 Windows 11 上原生运行、不要常驻服务或 Docker？装起来多重？

### Takeaway
能"一个可执行文件或一个 pip 包、无常驻服务、原生 Windows"的只有轻量一档：Task（go-task）、just、doit、DVC、Luigi（本地模式）、LangGraph/CrewAI/Agent Framework 这类纯库，以及 Mermaid/Graphviz/D2 这类画图工具。Nextflow、Airflow 官方只支持 WSL；Snakemake 官方说"也能在 Windows 跑"但安装页只写 Linux 和 WSL；Kestra、Windmill、Temporal、Prefect（要看界面时）、Dagster（要看界面时）、Argo 都要起一个服务进程，其中 Windmill 必须有 Postgres、Argo 必须有 Kubernetes。

### Cited Findings

**文件目标型**
- Snakemake：安装页只写"These instructions set out how to obtain and install the software on Linux"，Windows 一节写的是"If you use Windows 10, you can set up the Windows Subsystem for Linux"；安装方式为 pixi（官方称"the recommended way"）、conda、`pip install snakemake`。文档版本 9.27.1。【一手】— [Snakemake 安装页](https://snakemake.readthedocs.io/en/stable/getting_started/installation.html)
- Snakemake：教程页写"Snakemake, Pixi, and Miniforge work also under Windows"，但"the Windows shell is too different to be able to provide generic examples"。【一手】— [Snakemake 教程 Setup](https://snakemake.readthedocs.io/en/stable/tutorial/setup.html)
- Snakemake 在 Windows 上默认用 cmd.exe 执行命令，源码拒绝使用 `C:\Windows\System32` 下的 WSL `bash.exe`；有用户靠 `shell.executable()` 指向 Git Bash 跑通。【二手】（搜索摘要转述源码与 2023 年博客，未逐行核对）— [shell.py](https://www.github.com/snakemake/snakemake/blob/4816a58653e466ca94b1482a1d947a856f5381b3/snakemake/shell.py)；[liao961120 博客](https://liao961120.github.io/2023/02/15/snakemake/)
- Nextflow："Nextflow can be used on any POSIX-compatible system (Linux, macOS, etc)"，Windows 只能"through WSL"；需要 Bash 3.2+ 和 Java 17–26。【一手】— [Nextflow 安装页](https://docs.seqera.io/nextflow/install)
- DVC：安装方式含 `choco install dvc`、GitHub releases 页上的 Windows 自包含安装包、`pip install dvc`、conda。【一手】— [treeverse/dvc 仓库](https://github.com/treeverse/dvc)
- Task（go-task）："Task runs on Linux, macOS, and Windows"；用"embedded shell interpreter"（内置的命令解释器），不启动用户自己的 shell；要用特定 shell 时在命令里显式写 `bash`、`pwsh` 或 `cmd /c`。【一手】— [Task 平台与 shell](https://taskfile.dev/docs/guide/platforms)
- just："Linux, macOS, Windows, and other reasonable unixes are supported with no additional dependencies"；系统没有 `sh` 时要自己指定别的 shell。【一手】— [just 手册](https://just.systems/man/en/)
- doit：纯 Python 的任务工具，自述"Define tasks in Python. Run only what changed"。【一手】— [pydoit/doit 仓库](https://github.com/pydoit/doit)
- Luigi："Most Luigi functionality works on Windows"；但多 worker 进程（`--workers`）在 Windows 不支持、常报 `BrokenPipeError`；中央调度器以后台守护进程方式运行也不支持。【一手】— [Luigi Running](https://luigi.readthedocs.io/en/stable/running_luigi.html)
- GNU Make：本次没读 Windows 安装页。【未核实】

**代码优先的编排器**
- Dagster：需要 Python 3.11 以上（推荐 3.13）；安装页有 Windows 标签页和 PowerShell 命令；`pip install dagster dagster-webserver dagster-dg-cli`。【一手】— [Dagster 安装页](https://dagster.io/docs/getting-started/installation)

- Kestra：Windows 无 Docker 的走法是装 Java JRE 21、下载发行文件改名 `kestra.bat`、先装插件、`.\kestra.bat server local`，然后开 localhost:8080 登录；官方写"`server local` is suitable for local testing only"；最低 2 vCPU / 4 GiB 内存。【一手】— [Kestra Windows 安装](https://kestra.io/docs/installation/windows)；[Kestra 安装总览](https://kestra.io/docs/installation)
- Windmill：必须有 Postgres（"contains the entire state of Windmill, including the job queue"）；小规模用 Docker Compose；页面只说"run Windmill workers on Windows without Docker"，没说服务端能这样跑。【一手】— [Windmill self-host](https://www.windmill.dev/docs/advanced/self_host)
- Airflow："On Windows you can run it via WSL2 ... or via Linux Containers"，原生 Windows 支持"is not a high priority"（Airflow 3.4.0 文档）。【一手】— [Airflow Prerequisites](https://airflow.apache.org/docs/apache-airflow/stable/installation/prerequisites.html)
- Argo Workflows："you need a Kubernetes cluster and `kubectl` configured"；单机只能靠 minikube、kind、k3s/k3d 或 Docker Desktop 起一个本地集群。【一手】— [Argo Quick Start](https://argo-workflows.readthedocs.io/en/latest/quick-start/)

**智能体图框架（都是库，不是服务）**
- LangGraph：Python/JS 库，README 写"can be used without LangChain"。本地开发服务 `langgraph dev` 不需要 Docker，跑在 http://localhost:2024。【一手】— [langgraph 仓库](https://github.com/langchain-ai/langgraph)；[LangSmith local server](https://docs.langchain.com/langsmith/local-server)

- Mastra：TypeScript 框架。【一手】— [mastra 仓库](https://github.com/mastra-ai/mastra)
- Google ADK："Available in Python, TypeScript, Go, Java, and Kotlin"。【一手】— [adk.dev](https://adk.dev/)

**画图工具**
- Graphviz：Windows 有 64/32 位 EXE 安装包，另有 `winget install graphviz`、`choco install graphviz`；当前稳定版 16.1.1。【一手】— [Graphviz 下载页](https://graphviz.org/download/)
- D2：Go 写的命令行工具，可用安装脚本或 `go install`；Windows 的具体装法页面指向 docs/INSTALL.md，本次没读。【一手（前半）/未核实（Windows 装法）】— [terrastruct/d2 仓库](https://github.com/terrastruct/d2)

### Inferences
- 对"一个不写代码的人、Windows 11、不想养服务"来说，Nextflow、Airflow、Argo、Windmill 可以直接排除；Kestra、Temporal 虽然能在 Windows 起来，但本质就是要求 5 里说的"要装、要升级、要备份的常驻服务"。
- Snakemake 在 Windows 属于"官方承认能跑、但不给例子"的二等公民；工位命令是 `claude -p "..."` 这种普通命令行的话问题不大，但引号、路径、shell 差异会成为 AI 写规则时的常见出错点。
- 纯库型（LangGraph、CrewAI、Agent Framework、Mastra、ADK）不需要常驻服务，但意味着产线定义是一段程序，不是一个数据文件。

### Gaps
- Prefect、DVC、doit 在 Windows 上有没有已知的坑，本次没查 issue 列表。
- Temporal 开发服务关掉后再开，长跑流程能否无损续上，本次只确认了 `--db-filename` 能把状态落到文件，没有实测。
- Windmill 服务端能否原生跑在 Windows 上，官方页面没说。

## 2. 状态放在普通文件里，还是放在数据库/服务里？

### Takeaway
真正"状态就是文件本身"的是文件目标型工具：产出文件在不在、内容或时间戳变没变，就是状态；它们另有一个小的簿记目录（`.snakemake`、`dvc.lock`、`.task/`、doit 的签名库）。编排器和智能体框架几乎全把运行状态放进数据库：SQLite、H2、Postgres、LevelDB，最好的情况是"一个本地 SQLite 文件"，但那不是人能读、能交给新代理的半成品文件。

### Cited Findings
- Snakemake：是否重跑取决于产出文件和执行元数据（软件环境、非文件参数、输入文件集合）；`--summary` 能"Print a summary of all files created by the workflow"；`--touch` 把产出文件标成最新而不执行。【一手】— [Snakemake FAQ](https://snakemake.readthedocs.io/en/stable/project_info/faq.html)；[Snakemake CLI](https://snakemake.readthedocs.io/en/stable/executing/cli.html)
- DVC：每一站在 `dvc.yaml` 里写 `cmd`、`deps`（输入）、`outs`（产出）；依赖和产出的哈希值记在 `dvc.lock`（"the hash values of changed dependencies and outputs are updated in dvc.lock"）。【一手】— [DVC 定义流水线](https://doc.dvc.org/user-guide/pipelines/defining-pipelines)；[dvc repro](https://doc.dvc.org/command-reference/repro)
- Task：默认 `checksum` 方式，比较源文件内容与存下来的指纹；对产出只"checks that declared outputs exist; it does not compare their contents"；指纹放在项目目录下的 `.task/`。【一手】— [Task up-to-date](https://taskfile.dev/docs/guide/up-to-date)
- doit：每次任务成功后"saves the signature (MD5) of the dependencies"；目标文件不存在就执行。状态库的文件名页面没写。【一手】— [doit tasks](https://pydoit.org/tasks.html)
- Luigi：任务完成与否看 `complete()` 是否为真，约定是 `run()` 必须产出 `output()` 声明的全部目标；中央调度器的状态存到 `--state-path` 指定的文件；任务历史是可选的"experimental feature"，存进关系数据库。【一手】— [Luigi Tasks](https://luigi.readthedocs.io/en/stable/tasks.html)；[Luigi Central Scheduler](https://luigi.readthedocs.io/en/stable/central_scheduler.html)
- Nextflow：每个任务有按哈希命名的独立工作目录；缓存在 `.nextflow/cache`，底层是 LevelDB（一种嵌入式数据库），"can only be accessed by one reader/writer at a time"，所以运行中 `nextflow log` 查不了。【一手】— [Nextflow cache and resume](https://docs.seqera.io/nextflow/cache-and-resume)
- Dagster：设了 `DAGSTER_HOME` 后用 SQLite 存到本地：`history/runs.db`、每次运行一个 `history/[run_id].db`、日志在 `storage/[run_id]/compute_logs`；没设时"will use a temporary directory for storage that is cleaned up when the process exits"。【一手】— [Dagster instance](https://dagster.io/docs/deployment/dagster-instance)
- Prefect：自托管服务"backed by a database and a UI"，默认 SQLite，生产用 PostgreSQL 14.9+。【一手】— [Prefect server](https://www.prefect.io/docs/v3/concepts/server)
- Temporal：`start-dev` 默认"uses an in-memory SQLite database"，关了就没；加 `--db-filename temporal.db` 才落盘。状态是事件历史（Event History），不是产物文件。【一手】— [Temporal CLI 安装](https://docs.temporal.io/cli/setup-cli)；[Workflow Execution](https://docs.temporal.io/workflow-execution)
- Kestra：`server local` 用"H2 local file database"；最小示例配置里 `repository` 和 `queue` 都是 `type: memory`。【一手】— [Kestra standalone](https://kestra.io/docs/installation/standalone-server)；[Kestra Windows](https://kestra.io/docs/installation/windows)
- Windmill：Postgres"contains the entire state of Windmill, including the job queue"。【一手】— [Windmill self-host](https://www.windmill.dev/docs/advanced/self_host)
- LangGraph：检查点存储有 `InMemorySaver`（内存，重启即失）、`SqliteSaver`（"Local file-based storage for development"）、`PostgresSaver`；`langgraph dev` 的状态是"In-memory & pickled to local directory"。【一手】— [LangGraph persistence](https://docs.langchain.com/oss/python/langgraph/persistence)；[LangSmith local server](https://docs.langchain.com/langsmith/local-server)
- CrewAI Flows：`@persist` 的默认后端是 `SQLiteFlowPersistence`，可自己实现 FlowPersistence 接口换后端。【一手】— [CrewAI Flows](https://docs.crewai.com/concepts/flows)
- Microsoft Agent Framework：Python 版自带 `FileCheckpointStorage`，"persists checkpoints to a local directory on disk"，适合"Single-machine workflows"；非 JSON 原生的状态用 Python `pickle` 序列化（带受限反序列化）；Go 版有 `checkpoint.NewFileSystemJSONStore`。【一手】— [Agent Framework Checkpoints](https://learn.microsoft.com/en-us/agent-framework/workflows/checkpoints)
- OpenAI Agents SDK：`RunState` 可 `to_json()` / `to_string()` 存下来再 `from_json()` 恢复，示例把它写进本地 JSON 文件。【一手】— [OpenAI Agents SDK HITL](https://openai.github.io/openai-agents-python/human_in_the_loop/)
- Mastra：挂起时的快照"are stored in your configured storage provider and persist across deployments and application restarts"；页面没说默认是哪种存储。【一手】— [Mastra suspend and resume](https://mastra.ai/docs/workflows/suspend-and-resume)
- Backlog.md（不是引擎，是看板）："Everything is stored as human-readable Markdown in a project-local backlog folder"，每个任务是一个 `.md` 文件；自述"Local-first -- no server, no account, no telemetry"。【一手】— [Backlog.md README](https://cdn.jsdelivr.net/gh/MrLesk/Backlog.md@main/README.md)

### Inferences
- 设计标准要的是"每站的输入输出是固定位置、带状态的文件，任何一站能交给只拿到半成品和本站规格的新代理"。文件目标型工具天然满足前半句（产物是文件），但它们的"状态"只有"有/没有、新/旧"两种，没有"待验收、被退回第 2 次、等人判"这类业务状态，这部分要自己加一个状态文件。
- 编排器和智能体框架里的"状态"是引擎自己的运行记录（事件历史、检查点），不是半成品。即使落在本地 SQLite 或 pickle 文件里，也不是人能打开看、能直接交给另一个代理的东西。它们和要求 5 的"运行状态在数据库而不是文件"是同一类问题，只是数据库小一点。
- Agent Framework 的 `FileCheckpointStorage` 和 OpenAI 的 `RunState.to_json()` 是"框架状态落文件"里最接近的两个，但内容是框架内部结构，不是工位半成品。

### Gaps
- `.snakemake` 目录的具体内容、doit 状态库文件名、Prefect 本地 SQLite 的路径，本次读到的页面都没写明。
- Mastra 默认存储是否为本地文件型，未核实。

## 3. 能否表达"一站之后有门、不合格退回前面指定的某一站、带重试上限"？环（往回走）可不可以？

### Takeaway
文件目标型工具和 Dagster、Luigi、Airflow 这类都要求流程无环，只有"原地重试同一站"，没有"退回前面某一站"；常见绕法是把"做→检→改"的小循环塞进一站内部的脚本里，或者展开成固定次数的重复站。原生支持环的是 LangGraph（条件边 + 递归上限）、CrewAI Flows（router 自环）、Kestra（LoopUntil，只能重复自己的子任务块）、Mastra（dountil/dowhile，只能重复单步或子流程）、Temporal（普通代码循环）。其中只有 LangGraph 式的"条件边指回任意有名节点"和设计标准里的"退回指定站"是同一个形状。

### Cited Findings

**不许有环的**
- Snakemake："One limitation of Snakemake is that graphs of jobs have to be acyclic (similar to GNU Make)"；规则能生成自己的输入时会报 `PeriodicWildcardError`。【一手】— [Snakemake FAQ](https://snakemake.readthedocs.io/en/stable/project_info/faq.html)
- Snakemake 的近似手段：`retries` 指令给某条规则设自动重试次数，`attempt` 是当前第几次（从 1 起）；`ensure` 可检查产出"to be non-empty, or to compare them against a given sha256 checksum"；checkpoint（检查点规则）让引擎"re-evaluate the DAG after the successful execution of every job spawned from a checkpoint"，文档称"it is even possible to break a cyclic dependency"。【一手】— [Snakemake Rules](https://snakemake.readthedocs.io/en/stable/snakefiles/rules.html)
- DVC："in order for DVC to run a pipeline, its topology should be _acyclic_"，理由是"executing cycles (e.g. A -> B -> C -> A …) would continue indefinitely"；该页没有重试。【一手】— [DVC 定义流水线](https://doc.dvc.org/user-guide/pipelines/defining-pipelines)
- GNU Make：遇到环会报"Circular xxx <- yyy dependency dropped"，意思是"`make` detected a loop in the dependency graph"并把那条依赖丢掉。【一手】— [GNU Make Error Messages](https://www.gnu.org/software/make/manual/html_node/Error-Messages.html)
- just："Unknown recipes and circular dependencies are reported before anything runs"。【一手】— [just 手册](https://just.systems/man/en/)
- doit：README 列"DAG execution"，任务"run in correct dependency order"。【一手】— [pydoit/doit 仓库](https://github.com/pydoit/doit)
- Dagster：资产检查（asset check）是"tests that verify specific properties of your data assets"；默认检查失败后"the run will continue and downstream assets will be materialized"，设 `blocking=True` 才会拦住下游；页面没有"失败后自动重跑上游"。【一手】— [Dagster asset checks](https://dagster.io/docs/guides/test/asset-checks)
- Dagster 资产图不支持环。【二手】（社区论坛里的 AI 生成回答，官方页面本次没找到明文）— [Dagster 论坛帖](https://discuss.dagster.io/t/16601254/can-i-define-assets-that-update-each-other-in-a-circular-way)
- Luigi：`run()` 里 `yield` 另一个任务可动态加依赖（"the current task will be suspended and the other task will be run"），之后 `run()` 从头重来，所以必须幂等（重复执行结果一样）。该页没提环。【一手】— [Luigi Tasks](https://luigi.readthedocs.io/en/stable/tasks.html)

**能表达循环或退回的**
- Kestra：`LoopUntil`"runs a group of tasks repeatedly until a boolean condition evaluates to `true`"，`checkFrequency` 里有 `maxIterations`、`maxDuration`；`failOnMaxReached: true` 时到上限就失败（默认是 false，到上限算成功）。页面没有"跳回前面某个任务"的机制，循环只在块内部。【一手】— [Kestra flowable tasks](https://kestra.io/docs/workflow-components/tasks/flowable-tasks)
- Temporal：流程就是普通代码，持久执行"whether your code executes for seconds or years"；但流程代码必须是确定性的（重放时"the Commands that are generated are checked against an existing Event History"），不确定的活要放进 Activity。【一手】— [Temporal Workflow Execution](https://docs.temporal.io/workflow-execution)
- LangGraph：可以"build sequences, branches, and loops"；`add_conditional_edges` 的路由函数读当前状态、返回下一个节点名；`Command(goto=...)` 让节点一步里既改状态又指定去向；递归上限"caps how many super-steps one run may execute"，1.1.4 起默认 10,007，超了抛 `GraphRecursionError`，可用 `recursion_limit` 改；每个节点可挂 `RetryPolicy`。【一手】— [LangGraph Graph API](https://docs.langchain.com/oss/python/langgraph/graph-api)；[Use the graph API](https://docs.langchain.com/oss/python/langgraph/use-graph-api)
- CrewAI Flows：`@router()`做条件分支；循环的写法是让评审方法同时监听上游和自己的"要修改"结果，如 `@listen(or_("generate_draft", "needs_revision"))`；文档说"the flow engine exempts routers from the "fire once" rule"；注意 `@start()` 方法"only runs once"，所以示例里退回时重跑的是评审那一步，不是生成那一步。【一手】— [CrewAI human feedback in flows](https://docs.crewai.com/en/learn/human-feedback-in-flows)
- Mastra：`.dountil(step, 条件)`"run a step repeatedly until a condition becomes true"，`.dowhile` 相反；循环只能重复单步或嵌套子流程，文档没有 goto 或跳回有名步骤。【一手】— [Mastra control flow](https://mastra.ai/docs/workflows/control-flow)
- Google ADK：`LoopAgent`"executes its sub-agents in a loop for a specified number of iterations or until a termination condition is met"，Python 里 `max_iterations` 默认 `None`（只靠子代理"上报"才停）；该页标注模板式工作流已弃用，改用图式和动态工作流。【一手】— [ADK Loop agents](https://adk.dev/agents/workflow-agents/loop-agents/)
- Inngest AgentKit：网络是"while loops with memory"，路由器"chooses whether to stop or select the next agent to run in the loop"，`maxIter` 是可选的迭代上限。【一手】— [AgentKit Networks](https://agentkit.inngest.com/concepts/networks)
- Windmill：文档侧栏有"While loops"和 Retries（"Retry a step until it is successful"），本次没读详情。【一手（存在）/未核实（语义）】— [Windmill flow approval](https://www.windmill.dev/docs/flows/flow_approval)

**画图语言本身**
- Mermaid 流程图允许往回指的边（官方示例里有 `D --> B`）。【一手】— [Mermaid flowchart](https://mermaid.js.org/syntax/flowchart.html)

### Inferences
- "退回前面指定的一站、最多 N 次、超了转人工"在本次读到的工具里，只有 LangGraph 能几乎原样写出来（条件边指向任意节点 + 自己在状态里记次数 + 全局递归上限兜底）。CrewAI Flows 能做但写法绕，且文档自己的例子就暴露了"退回后生成步骤不重跑"的坑。
- 文件目标型工具的通用绕法有三种，各有代价：(a) 把"做→检→改"循环写进一站的脚本，引擎只看到一个站——门和退回对流程图不可见，违背"每站一道门"；(b) 把循环展开成"第 1 轮、第 2 轮、第 3 轮"固定几组站——图变长但仍无环，且只能退回到本轮起点；(c) 外面再包一个脚本反复调 `snakemake`/`dvc repro`，由脚本删掉不合格的产物来触发重跑——这其实已经是自己写引擎了。
- Snakemake 的 `ensure` + `retries` 只覆盖"机器判、原地重做"，不是"退回上游"。
- Kestra 的 `failOnMaxReached` 默认值是"到上限算成功"，如果拿它当门，必须显式改成 true，否则次品会被放行。

### Gaps
- Microsoft Agent Framework 的图是否允许往回的边、上限怎么设，本次只读了检查点和可视化两页，没读执行模型页。【未核实】
- ADK 2.0 图式工作流的路由能否指回前面节点，"Graph routes"页本次没读。【未核实】
- Dagster、Luigi 对环的官方表述本次没找到一手原文。
- Prefect 流程是普通 Python，按常理可以写 while 循环，但本次没读到官方关于"循环 + 任务重试"的页面。【未核实】

## 4. 能否停下来等人判断，之后从文件恢复？

### Takeaway
文件目标型工具没有"等人"的概念（最多是命令行里问一句确认）。有正式"暂停—恢复"的是 Prefect、Kestra、Windmill（都靠服务和界面）以及 LangGraph、CrewAI、Agent Framework、ADK、Mastra、OpenAI Agents SDK（靠检查点）。恢复都依赖引擎自己的存储，没有一个是"人改一个文件就算批了"。

### Cited Findings
- Snakemake：规则文档里没有暂停功能，最接近的只是笔记本交互编辑模式。【一手】— [Snakemake Rules](https://snakemake.readthedocs.io/en/stable/snakefiles/rules.html)
- Task：条件执行一节包含"asking for confirmation"和 `preconditions`。【一手】— [Task Guide](https://taskfile.dev/docs/guide)
- Prefect："Flows can pause or suspend execution and automatically resume when they receive type-checked input in Prefect's UI"；`pause_flow_run` / `suspend_flow_run` 配 `wait_for_input`；挂起会"exits the flow and tears down infrastructure"。示例需要"a deployed flow"和 Prefect Cloud 或自托管服务。【一手】— [Prefect interactive workflows](https://www.prefect.io/docs/v3/advanced/interactive)
- Kestra：`Pause`"halts the execution until it is manually resumed or a timeout expires"，可从界面的 Gantt 页或 API 恢复；超时行为可设 `RESUME`、`WARN`、`CANCEL`、`FAIL`。【一手】— [Kestra flowable tasks](https://kestra.io/docs/workflow-components/tasks/flowable-tasks)
- Windmill：步骤可设"Suspend until approval/resume"；审批通过专用的 resume URL 或审批页；可设超时，"Continue on disapproval/timeout"让流程走到下一步以便接分支。【一手】— [Windmill flow approval](https://www.windmill.dev/docs/flows/flow_approval)
- LangGraph：在节点里调 `interrupt()` 即暂停；必须有检查点存储和 `thread_id`；用 `Command(resume=...)` 恢复，"The value passed to `Command(resume=...)` becomes the return value of the interrupt call"；注意"The node restarts from the beginning of the node where the interrupt was called when resumed"，所以 `interrupt()` 之前的代码会再跑一遍，必须幂等。可无限期等待。【一手】— [LangGraph interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts)
- CrewAI Flows：`@human_feedback`（1.8.0 起）暂停收集人的自由文本反馈；带 `emit=[...]` 时由一个 LLM 把反馈归到指定结果之一；异步模式下抛 `HumanFeedbackPending`，之后 `ReviewFlow.from_pending(flow_id)` 再 `flow.resume(feedback)`；"State is automatically saved ... and uses `SQLiteFlowPersistence` by default"。【一手】— [CrewAI human feedback in flows](https://docs.crewai.com/en/learn/human-feedback-in-flows)
- Microsoft Agent Framework：有独立的 Human-in-the-loop 能力（"Pause for external input and resume execution"）；检查点里包含"Pending requests and responses"；可在新进程里用同样结构的流程从检查点恢复（"rehydrate a new workflow instance from a checkpoint"）。【一手】— [Agent Framework Workflows](https://learn.microsoft.com/en-us/agent-framework/workflows/)；[Checkpoints](https://learn.microsoft.com/en-us/agent-framework/workflows/checkpoints)
- Google ADK：图节点产出 `RequestInput` 即暂停，"pauses the execution of the agent until the system receives an input from a user"；默认恢复时被打断的节点不重跑。【一手】— [ADK graph human input](https://adk.dev/graphs/human-input/)
- Mastra：步骤里调 `suspend()` 暂停，状态变 `suspended`；`resume()` 带符合 `resumeSchema` 的数据恢复；可先 `createRun({ runId })` 再恢复。【一手】— [Mastra suspend and resume](https://mastra.ai/docs/workflows/suspend-and-resume)
- OpenAI Agents SDK：人工环节是"工具调用审批"：工具设 `needs_approval`，运行暂停并在 `RunResult.interruptions` 列出待批项；`state.approve()` / `state.reject()` 后恢复；状态可存成 JSON 文件跨进程恢复。【一手】— [OpenAI Agents SDK HITL](https://openai.github.io/openai-agents-python/human_in_the_loop/)
- Temporal 用 Signal（信号）接收外部输入；本次读的页面只说 Signal 用于流程之间通信，没专门讲人工输入。【一手（Signal 存在）/未核实（人工审批用法）】— [Temporal Workflow Execution](https://docs.temporal.io/workflow-execution)

### Inferences
- 对"门由人判"这件事，文件式的最简实现是：引擎把该件的状态文件写成"等人判"并停手，人（或聊天框里的 AI 代人）把判定写回文件，下次运行引擎读到判定再继续。本次读到的现成工具没有一个这样做，它们的暂停状态都在自己的库里。
- LangGraph 恢复时整节点重跑这一点，对"一站要跑几分钟的 `claude -p`"很要紧：人工门必须是单独一个节点，不能和干活写在同一个节点里。
- OpenAI Agents SDK 的人工环节是"批不批这次工具调用"，粒度和"验收这件半成品"不是一回事。

### Gaps
- DVC、doit、just、Luigi、Dagster 有没有任何形式的人工暂停，本次没查到，也没读到否定的明文。

## 5. 能否把"耗时长、结果不稳定的命令行"当一站跑，并让很多件活同时处在不同工位？

### Takeaway
所有文件目标型工具的站本来就是一条 shell 命令，跑几分钟没问题；它们按文件名通配来处理"很多件"，Snakemake、Nextflow 能并行，DVC 明说没有内建并行。但它们都假设命令是确定的（同样输入出同样结果），"结果时好时坏"只能靠重试和检查兜。编排器和智能体框架要自己用代码包一层子进程调用。

### Cited Findings
- DVC：每站的 `cmd`"wraps an executable shell command"；没有内建并行，官方建议在多个终端里分别跑 `dvc repro A2`、`dvc repro B2`，否则"it would reproduce each branch sequentially"；没有依赖和产出的站"always considered changed and always run"。【一手】— [DVC 定义流水线](https://doc.dvc.org/user-guide/pipelines/defining-pipelines)；[dvc repro](https://doc.dvc.org/command-reference/repro)
- Snakemake：`--keep-going`"Go on with independent jobs if a job fails during execution"；`--rerun-incomplete`"Re-run all jobs the output of which is recognized as incomplete"；`--retries`"Number of times to restart failing jobs"。【一手】— [Snakemake CLI](https://snakemake.readthedocs.io/en/stable/executing/cli.html)
- Nextflow：每个任务执行都进缓存；`-resume` 时若缓存命中且产出还在就跳过，否则重跑；任务哈希里含一个"通常跟踪重试次数"的递增量。【一手】— [Nextflow cache and resume](https://docs.seqera.io/nextflow/cache-and-resume)
- Luigi：中央调度器不执行任务，只"Make sure two instances of the same task are not running simultaneously"和提供可视化；Windows 上多 worker 不可用。【一手】— [Luigi Central Scheduler](https://luigi.readthedocs.io/en/stable/central_scheduler.html)；[Luigi Running](https://luigi.readthedocs.io/en/stable/running_luigi.html)
- Task：有按"values, files and matrices"循环重复命令或任务的功能，可控制并发。【一手】— [Task Guide](https://taskfile.dev/docs/guide)
- Temporal：每个流程执行"has exclusive access to its local state"并与其他执行并发；流程代码必须确定，非确定的工作通过 Activity 与外界交互。【一手】— [Temporal Workflow Execution](https://docs.temporal.io/workflow-execution)
- LangGraph：每件活对应一个 `thread_id`，"using a new value starts a brand-new thread with an empty state"。【一手】— [LangGraph interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts)
- Mastra：`.foreach(step, { concurrency: N })`，默认并发 1；可把整个子流程当作 foreach 的一步（每件一条完整流水线）。【一手】— [Mastra control flow](https://mastra.ai/docs/workflows/control-flow)
- OpenAI Agents SDK 提醒：审批不保证恰好执行一次，有副作用的工具需要幂等键。【一手】— [OpenAI Agents SDK HITL](https://openai.github.io/openai-agents-python/human_in_the_loop/)

### Inferences
- "很多件活各自停在不同工位"这件事，文件目标型工具是用"每件一组文件名"天然实现的：哪件的哪个产出文件存在，它就过了哪一站。这正是设计标准想要的形态，也是这类工具最值得借的地方。
- 这类工具的缓存逻辑（输入没变就不重跑）和 LLM 工位有冲突：门没过时输入并没变，引擎会认为"已是最新"。要重做就得删产物或强制重跑（Snakemake `--forcerun`、DVC `--force`、Task `--force`），这一步谁来做、做几次，又落回到要自己写的那层逻辑。
- 个人自用、几分钟一站的量级，并行不是主要矛盾；顺序执行或简单的"同时跑 N 件"就够。

### Gaps
- 各工具对"单站超时后杀掉子进程"的支持（对卡住的 `claude -p` 很重要），本次没逐个查。
- Windows 上长跑子进程被中断后的清理行为，没有一手资料。

## 6. 自带什么可视化？不写代码的人看得懂吗？

### Takeaway
文件目标型工具只出"静态结构图"（DOT 或 Mermaid 文本），不显示哪件在哪站；Snakemake 和 DVC 都能直接吐 Mermaid。带实时界面的（Dagster、Prefect、Temporal、Kestra、Windmill、Luigi、Mastra Studio、LangGraph Studio、ADK Web）都要开着服务，且界面是给工程师看运行记录的。没有一个现成工具给出"以半成品文件为准、每件活在哪一站"的看板；最接近这个形态的是不属于引擎的 Backlog.md（Markdown 文件即看板）。

### Cited Findings
- Snakemake：`--dag`"print the directed acyclic graph of jobs in the dot language or in mermaid-js"；`--rulegraph` 出规则级的图；`--filegraph` 出带输入输出文件的图（DOT）；`--report` 生成"self-contained HTML report"；`--summary` 列出所有产出文件的概况。【一手】— [Snakemake CLI](https://snakemake.readthedocs.io/en/stable/executing/cli.html)
- DVC：`dvc dag` 默认在终端画字符图；`--mermaid`"show DAG in Mermaid format"；`--md` 包成 Markdown 代码块；`--dot` 出 DOT；`--outs` 改画产出文件之间的依赖。不显示运行状态。【一手】— [dvc dag](https://doc.dvc.org/command-reference/dag)
- Nextflow：`-with-dag` 默认生成 HTML 并用 Mermaid 渲染；加 `-preview` 可"render the workflow DAG without executing any tasks"；`-with-trace` 生成 CSV，每个任务一行，含 `status`、`exit`、`duration` 等列；`-with-report`、`-with-timeline` 生成 HTML 报告。【一手】— [Nextflow reports](https://docs.seqera.io/nextflow/reports)
- Luigi：中央调度器"Provide visualization of everything that's going on"，默认端口 8082；README 称可"search and filter among all your tasks"。【一手】— [Luigi Central Scheduler](https://luigi.readthedocs.io/en/stable/central_scheduler.html)；[luigi 仓库](https://github.com/spotify/luigi)
- LangGraph：`graph.get_graph().draw_mermaid()` 输出 Mermaid 文本，用来"review topology and debug routing"。【一手】— [Use the graph API](https://docs.langchain.com/oss/python/langgraph/use-graph-api)
- LangGraph Studio（现归 LangSmith）："specialized agent IDE that enables visualization, interaction, and debugging"，显示图结构、走过的节点、中间状态，支持时间回溯；本地用法是 `langgraph dev` 起服务后打开 `https://smith.langchain.com/studio/?baseUrl=http://127.0.0.1:2024`——界面托管在 LangSmith 网站上；前置条件列了"An API key for LangSmith (free to sign up)"。【一手】— [LangSmith Studio](https://docs.langchain.com/langsmith/studio)；[LangSmith local server](https://docs.langchain.com/langsmith/local-server)
- CrewAI Flows：`flow.plot("name")`"will create an HTML file containing the interactive plot of your flow"，命令行等价物是 `crewai flow plot`；router 的分支只有声明了标签才画得出来。【一手】— [CrewAI Flows](https://docs.crewai.com/concepts/flows)
- Microsoft Agent Framework：`WorkflowViz(workflow)` 可 `to_mermaid()`、`to_digraph()`（DOT），导出 svg/png/pdf 需装 Graphviz；起点绿色、条件边虚线并标"conditional"；Go 版没有内置渲染。【一手】— [Agent Framework Visualization](https://learn.microsoft.com/en-us/agent-framework/workflows/visualization)
- Mastra Studio：Workflows 页签有图视图，"The center panel visualizes the workflow's steps and execution flow"，运行时显示各步实时状态，可按输入规格自动生成输入表单，运行后可"replay individual steps to inspect or retry them"。【一手】— [Mastra workflows overview](https://mastra.ai/docs/workflows/overview)
- Google ADK：有"Web Interface"（截图标"ADK Web Dev UI"）和"Visual Builder"。【一手】— [adk.dev](https://adk.dev/)
- Kestra：界面在 localhost:8080，暂停的执行从 Gantt 页恢复。【一手】— [Kestra Windows](https://kestra.io/docs/installation/windows)；[Kestra flowable tasks](https://kestra.io/docs/workflow-components/tasks/flowable-tasks)
- Mermaid：`classDef` 可给节点定义填充色等样式，再用 `class 节点 类名` 或 `:::` 套上；支持 `subgraph` 分组；节点可绑定点击事件或链接（`securityLevel='strict'` 时禁用）。【一手】— [Mermaid flowchart](https://mermaid.js.org/syntax/flowchart.html)
- D2：`d2 --watch in.d2 out.svg` 会开浏览器窗口，`.d2` 文件一改就自动刷新；可导出 SVG、PNG、GIF、PDF、PPTX。【一手】— [terrastruct/d2 仓库](https://github.com/terrastruct/d2)
- React Flow：一个 React 组件，传入节点和连线对象即渲染；官方示例含自定义节点、"Editable Edge"、"Reconnect Edge"、"Drag and Drop"。【一手】— [React Flow Learn](https://reactflow.dev/learn)
- Backlog.md：`backlog board` 在终端显示实时看板；`backlog browser` 起一个只监听 127.0.0.1 的本地网页看板，支持拖拽和任务编辑表单；`backlog board export` 导出 Markdown 报告。【一手】— [Backlog.md README](https://cdn.jsdelivr.net/gh/MrLesk/Backlog.md@main/README.md)

### Inferences
- "给不写代码的人审流程"需要的图是：站名用大白话、每站下面写门的标准、退回箭头标上"最多几次"。现成工具自动生成的图节点名是规则名或函数名，没有门和退回的信息，都要再加工。所以无论选不选引擎，"从产线定义文件生成一张人话 Mermaid 图"这一步都得自己写。
- Mermaid 是本次看到的最大公约数：Snakemake、DVC、Nextflow、LangGraph、Agent Framework 都输出它，它允许回头箭头，能用 `classDef` 按状态上色。用它既能画"设计图"，也能叠加"每站现在有几件"画成"实时图"。
- "每件在哪站"的实时视图，如果状态本来就是文件，扫一遍目录就能生成（一张表或一张上了色的 Mermaid 图），不需要常驻界面。Backlog.md 证明了"Markdown 文件 + 命令行看板 + 临时本地网页"这种形态是成立的，可以借它的做法，甚至考虑直接把它当看板用（后者是推测，未验证其状态列能否自定义成工位名）。
- LangGraph Studio 虽好看，但界面托管在厂商网站并要求注册拿 API key，与"个人自用、不依赖外部服务"相悖。

### Gaps
- Dagster、Prefect、Temporal 界面的具体样子和可读性，本次没读对应页面，只知道它们存在。【未核实】
- Mermaid 图在用户实际会用的查看器里（Claude Code 桌面端、VS Code、浏览器）各自怎么渲染，本次没查。
- Backlog.md 的状态列是否可自定义为任意工位名：README 指向 ADVANCED-CONFIG.md，本次没读。

## 7. 产线定义是不是 AI 能可靠地写、校验（干跑/查错）、修改的简单文本文件？

### Takeaway
最适合 AI 写和改的是声明式数据文件：DVC 的 `dvc.yaml`、Task 的 `Taskfile.yml`、Kestra 的 YAML 流程。Snakemake 的 Snakefile 是带 Python 的专用语法，但自检手段最全（`--dry-run`、`--lint`、`--dag`）。LangGraph、CrewAI、Mastra、Temporal、Dagster、Prefect、Luigi、doit 的定义都是程序代码，没有"干跑"，校验只能靠真跑或写测试。

### Cited Findings
- Snakemake：`--dry-run`/`-n`"Do not execute anything, and display what would be done"；`--lint`"Perform linting on the given workflow"；干跑时还会打印调度计划。【一手】— [Snakemake CLI](https://snakemake.readthedocs.io/en/stable/executing/cli.html)
- DVC：`dvc repro --dry`"only print the commands that would be executed without actually executing the commands"；DVC 会校验项目里所有 `dvc.yaml`；`dvc stage add` 可用命令生成站，但"doesn't support advanced features like templating"。【一手】— [dvc repro](https://doc.dvc.org/command-reference/repro)；[DVC 定义流水线](https://doc.dvc.org/user-guide/pipelines/defining-pipelines)
- Nextflow：`-preview` 配 `-with-dag` 不执行任务就画出流程图；存在 stub run（桩运行，用假命令走一遍）概念。【一手】— [Nextflow reports](https://docs.seqera.io/nextflow/reports)；[Nextflow cache and resume](https://docs.seqera.io/nextflow/cache-and-resume)
- Task：`--status`"Checks whether tasks are up to date without running their commands"，有任务不是最新就返回非零退出码；指南提到"previewing commands"。【一手】— [Task up-to-date](https://taskfile.dev/docs/guide/up-to-date)；[Task Guide](https://taskfile.dev/docs/guide)
- just：未知配方和循环依赖"are reported before anything runs"。【一手】— [just 手册](https://just.systems/man/en/)
- doit：定义文件叫 dodo 文件，是 Python 模块，"A function that starts with the name task_ defines a task-creator"，返回或产出字典。【一手】— [doit tasks](https://pydoit.org/tasks.html)
- Kestra：流程用 YAML 声明，通过界面或 API 做的修改会写回 YAML。【一手】— [kestra 仓库](https://github.com/kestra-io/kestra)
- Windmill：流程可在可视编辑器里搭或写成 YAML，`wmill` 命令行可把工作区和本地文件、Git 双向同步。【一手】— [windmill 仓库](https://github.com/windmill-labs/windmill)
- Microsoft Agent Framework：有"Declarative workflows"（"Define supported workflows through declarative configuration"）。【一手】— [Agent Framework Workflows](https://learn.microsoft.com/en-us/agent-framework/workflows/)
- CrewAI Flows：流程是带 `@start`、`@listen`、`@router` 装饰器的 Python 类。【一手】— [CrewAI Flows](https://docs.crewai.com/concepts/flows)
- Mastra：流程用 `createWorkflow()`、`createStep()`（带 `inputSchema`/`outputSchema`）、`.then()`、`.commit()` 的 TypeScript 代码定义。【一手】— [Mastra workflows overview](https://mastra.ai/docs/workflows/overview)
- Agent Framework 的检查点要求恢复时流程"must preserve the topology and executor identities"，结构一改旧检查点就对不上。【一手】— [Agent Framework Checkpoints](https://learn.microsoft.com/en-us/agent-framework/workflows/checkpoints)

### Inferences
- 要求 3（AI 自己验证跑得通）最需要两样东西：不花钱不耗时的结构自检（干跑、查环、查每站有没有门、退回目标存不存在），以及用小样本真跑一遍。前者 Snakemake/DVC/Task 都有现成命令；后者任何工具都得真跑。
- 要求 8（人能手改图，主要是人提意见 AI 改）意味着"定义文件是唯一真相、图从它生成"最省事。定义是数据文件（YAML/JSON/TOML）时，AI 改一处、重新生成图、再自检，三步都机械；定义是代码时，图和代码容易对不上（CrewAI 自己就提示 router 分支不声明标签就画不出来）。
- 流程结构一改、旧运行状态作废，这是检查点式引擎的通病（Agent Framework 明文写了）。状态若是"每件一个目录、每站一个产物文件"，改流程后旧件最多是多出或缺几个文件，容易人工判断。

### Gaps
- LangGraph 有没有"不运行就校验图结构"的官方命令，本次没查到。【未核实】
- Kestra 的 YAML 有没有离线校验命令，本次没读。【未核实】
- Task 的 `--dry` 具体行为页面没读到原文。【未核实】

## 9. 逐个结论：适不适合当发动机（好 / 绕一绕能用 / 差），决定性理由

### Takeaway
没有一个是"好"。"绕一绕能用"的有两类：一类是文件型里的 Snakemake、Task、DVC、doit（文件和干跑都对路，但不许回头、没有人工门）；另一类是 LangGraph（回头、暂停、上限都对路，但状态在检查点库里、定义是代码、好看的界面在厂商网站上）。其余都是"差"，理由集中在三条：要常驻服务、不支持 Windows 原生、状态在数据库。

### Cited Findings
以下每条结论所依据的事实都已在前面各节给出出处，这里只列结论和决定性理由，并重复给出最关键的一条出处。

**文件目标型**
- Snakemake——**绕一绕能用**。对路：产物即状态、`--dry-run`/`--lint`、直接出 Mermaid、`ensure` + `retries` 能当机器门。不对路：流程必须无环、没有人工门、Windows 是二等公民。— [FAQ：graphs of jobs have to be acyclic](https://snakemake.readthedocs.io/en/stable/project_info/faq.html)
- Nextflow——**差**。Windows 只能走 WSL，还要 Java。— [安装页](https://docs.seqera.io/nextflow/install)
- DVC 流水线——**绕一绕能用，但偏弱**。`dvc.yaml` 是 AI 最容易写的格式，`dvc dag --mermaid` 现成；但明文禁止环、没有重试、没有内建并行、没有人工门。— [定义流水线](https://doc.dvc.org/user-guide/pipelines/defining-pipelines)
- GNU Make——**差**。遇环直接丢依赖，无状态概念之外的任何东西。— [Error Messages](https://www.gnu.org/software/make/manual/html_node/Error-Messages.html)
- just——**差**。自我定位是"a command runner, not a build system"，循环依赖在运行前就报错。— [just 手册](https://just.systems/man/en/)
- Task（go-task）——**绕一绕能用**。跨平台、内置 shell 解释器、YAML、有 `status`（可当机器门）、`preconditions`、确认提示、`--status` 自检；但仍是无环依赖，退回要外面包脚本。— [up-to-date](https://taskfile.dev/docs/guide/up-to-date)
- doit——**绕一绕能用**。纯 Python、按文件签名判断是否重跑；但定义是代码、DAG、无人工门。— [doit tasks](https://pydoit.org/tasks.html)
- Luigi——**差**。Windows 上多 worker 和后台调度器都不可用，定义是 Python 类，看图要起中央调度器。— [Running Luigi](https://luigi.readthedocs.io/en/stable/running_luigi.html)

**代码优先的编排器**
- Dagster——**差**。资产检查只能"拦住下游"，不能退回上游；状态在 SQLite；看图要起网页服务。— [asset checks](https://dagster.io/docs/guides/test/asset-checks)
- Prefect——**差**。人工暂停要靠界面和服务；没有服务时每次运行起临时服务、界面里看不到。— [interactive](https://www.prefect.io/docs/v3/advanced/interactive)；[quickstart](https://www.prefect.io/docs/v3/get-started/quickstart)
- Temporal——**差**。能力最强（循环、长跑、恢复都行），但要常驻服务加 Worker 进程，状态是事件历史，流程代码有确定性约束，对个人自用过重。— [Workflow Execution](https://docs.temporal.io/workflow-execution)
- Kestra——**差**。YAML + `LoopUntil` + `Pause` + 界面，功能上最像"门 + 重做 + 等人"，但它就是要求 5 排除的那种东西：JVM 常驻服务、状态在 H2/Postgres、官方说本地模式只适合测试。— [Windows 安装](https://kestra.io/docs/installation/windows)
- Windmill——**差**。必须 Postgres，服务端原生 Windows 未见支持。— [self-host](https://www.windmill.dev/docs/advanced/self_host)
- Airflow——**差**。不支持原生 Windows。— [Prerequisites](https://airflow.apache.org/docs/apache-airflow/stable/installation/prerequisites.html)
- Argo Workflows——**差**。必须 Kubernetes。— [Quick Start](https://argo-workflows.readthedocs.io/en/latest/quick-start/)

**智能体图框架**
- LangGraph——**绕一绕能用**（这一类里最接近）。条件边可指回任意节点、有递归上限、`interrupt()` 可无限期等人、可出 Mermaid。不对路：状态在检查点库（SQLite 文件）而不是工位半成品文件；定义是 Python 代码；恢复时整节点重跑；Studio 界面托管在 LangSmith 并要 API key。— [interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts)；[graph API](https://docs.langchain.com/oss/python/langgraph/graph-api)
- CrewAI Flows——**差到勉强能用**。能循环、能等人、能出 HTML 图，但循环写法绕（`@start` 只跑一次），状态在 SQLite，人的反馈默认还要过一道 LLM 归类。— [human feedback in flows](https://docs.crewai.com/en/learn/human-feedback-in-flows)
- Microsoft Agent Framework——**绕一绕能用，待核实**。有本地目录检查点、人工环节、Mermaid/DOT 导出、声明式流程；但检查点是 pickle、流程结构一变旧检查点作废；是否支持回头边本次未核实。— [Checkpoints](https://learn.microsoft.com/en-us/agent-framework/workflows/checkpoints)
- AutoGen——**差**。一年多无发布。— [API](https://api.github.com/repos/microsoft/autogen/releases/latest)
- Google ADK——**差到勉强能用，待核实**。旧的 LoopAgent 已标弃用，新的图式工作流有人工输入节点；会话存储和回头路由本次未核实。— [Loop agents](https://adk.dev/agents/workflow-agents/loop-agents/)；[human input](https://adk.dev/graphs/human-input/)
- OpenAI Agents SDK——**差**。人工环节只是工具调用审批；本次读到的页面没有图式流程引擎。— [HITL](https://openai.github.io/openai-agents-python/human_in_the_loop/)
- Mastra 工作流——**差到勉强能用**。有循环、挂起恢复、带实时状态的 Studio 图；但是 TypeScript 代码、只能重复单步或子流程、状态在存储提供方里。— [control flow](https://mastra.ai/docs/workflows/control-flow)
- Inngest AgentKit——**差**。一年无发布，模型是"代理网络的 while 循环"而不是工位产线。— [Networks](https://agentkit.inngest.com/concepts/networks)

**当流程图用**
- Mermaid——**好**（当图）。纯文本、AI 易生成、允许回头箭头、可按状态上色、多个流水线工具原生输出它。— [flowchart](https://mermaid.js.org/syntax/flowchart.html)
- Graphviz——**能用**。老牌、Windows 有安装包；DOT 文本对普通人不如 Mermaid 好读，且要装程序。— [下载页](https://graphviz.org/download/)
- D2——**能用**。`--watch` 实时预览是亮点；要多装一个工具。— [仓库](https://github.com/terrastruct/d2)
- React Flow——**只有当"人要用鼠标拖着改图"成为硬需求时才值得**。它是做编辑器的零件，不是现成的看图工具，要搭 React 项目。— [Learn](https://reactflow.dev/learn)
- Backlog.md——**值得当"每件在哪站"看板的参照物**，不是引擎。— [README](https://cdn.jsdelivr.net/gh/MrLesk/Backlog.md@main/README.md)

### Inferences
- 两类"能用"的候选恰好互补：文件型的强项（文件即状态、干跑、文本定义）是 LangGraph 的弱项；LangGraph 的强项（回头、等人、上限）是文件型的弱项。没有一个同时占两头。
- 拿 LangGraph 当底座要写的胶水：每个节点里读写固定位置的半成品文件、门节点、次数计数、把定义从某个数据文件翻译成图、生成人话 Mermaid、扫目录出状态。这些胶水加起来和自己写一个小引擎的量差不多，而换来的是一个更新很勤（当天还在发版）的依赖和一套与"文件即状态"重复的检查点机制。
- 拿 Snakemake/Task 当底座要写的胶水：外层循环脚本负责"门没过→删产物→记次数→重跑→超限转人工"，以及人工门。底层的"按文件判断哪些要跑"是白拿的，但对 LLM 工位这项能力价值有限（真正的判断是门，不是时间戳）。

### Inferences
以下全部是基于上面事实的工程判断，不是读到的事实。

**自己写的发动机必须做的事（最小集）**
1. 读一个产线定义文件（YAML 或 JSON）：站的顺序；每站的输入文件、产出文件、命令模板；每站的门（机器判：一条检查命令或格式校验；人判：停下等）；门不过退回哪一站；每条退回路的次数上限；整条线的退场条件（只是写明的文字，引擎不必执行）。
2. 每件活一个目录，里面是各站产物文件加一个状态文件（现在在哪站、每条退回路已用几次、最后一次门的结论和理由、是否在等人）。
3. 跑一步：按状态找到该做的站，用子进程跑命令（带超时），产物先写临时名再改名。
4. 过门：机器门看检查命令的退出码；人工门把状态写成"等人判"然后停手，下次运行读到人写回的结论再继续。
5. 退回：门不过就计数加一、把状态指回指定站；超上限就标"卡住，转人工"，绝不默默放行。
6. 自检（给要求 3 用）：不运行就能查——退回目标是否存在、每站是否有门、每条退回路是否有上限、从第一站能否走到最后一站、命令模板里引用的文件是否有上游产出；再加一个"用样例原料真跑一件"的命令。
7. 出图：从定义文件生成 Mermaid 流程图（站名、门的标准、退回箭头带上限）；再扫各件的状态文件，生成"每站现在有几件、哪些在等人、哪些卡住"的表或上色图。
8. 一把简单的锁，防止同一件活被两个进程同时推进。

**可以不做的事**
常驻进程、数据库、网页界面服务、用户与权限、分布式执行、定时调度、按内容哈希的缓存与增量重算、插件体系、复杂并行（顺序跑或"同时 N 件"即可）、可视化拖拽编辑器（先让 AI 改定义文件、图自动重生成；手改就是改那个文本文件）。

**规模估计**
- 核心推进逻辑（第 1–5、8 项）约 300–500 行 Python；自检（第 6 项）约 100–200 行；出图与状态汇总（第 7 项）约 100–200 行。合计大约 500–900 行，一到三个文件，除标准库外最多依赖一个 YAML 解析包（改用 JSON 则零依赖）。
- 这个数字是估计，没有原型佐证；误差主要来自 Windows 上子进程超时与清理、命令模板里的引号和路径处理，这两处容易比预想的多。
- 对照：用 LangGraph 当底座，胶水量与此相当，却多出一份检查点状态和一个高频更新的依赖；用 Snakemake/Task 当底座，白拿的是"按文件决定跑哪些"，而这恰好不是 LLM 工位的难点。

**值得借而不是重写的**
- 图：Mermaid（文本、AI 好写、能回头、能上色、生态里到处都认）。只有当"鼠标拖着改图"变成硬需求时才上 React Flow。
- 定义文件的词汇：`cmd`/`deps`/`outs`（DVC）、`status`/`preconditions`（Task）、`ensure`/`retries`/`attempt`（Snakemake）、`maxIterations`/`failOnMaxReached`（Kestra）。沿用这些词，AI 写起来更不容易错，将来想换成真引擎也好迁移。
- 命令行的分工：`dry-run`、`lint`、`dag`、`summary` 四个命令（Snakemake 的划分）。
- 看板形态：Backlog.md 的"文件即看板、需要时才起本地网页"。

**"采用现成"与"自己写"的分界线**
- 如果将来需求变成多人协作、定时触发、上百件并发、要审计日志，Kestra 或 Temporal 才开始划算。
- 如果想要一个折中：先自己写最小引擎，定义文件格式故意贴近 DVC/Task 的词汇，这样万一要迁到现成工具，迁的是执行层，定义和半成品文件都不用动。
