# 产线文件与接口（2026-11-14）

三块东西之间的约定：执行器（`app/engine.py`）、本机服务（`app/server.py`）、画布页面（`app/web/`）。改任何一块之前先看这里；改了约定要同步改这份文档。

（2026-11-14 用户定）执行器自己写，不用 conductor。理由：画布页面接管了流程图、人工验收、断点续跑之后，conductor 只剩分流和步数上限两样用得上，继续用反而要多写翻译层、状态存两处。conductor 留在电脑上不删。

## 一条线在磁盘上的样子

```
lines/<线的英文名>/
  line.json            这条线的唯一定义（站、门、规格、标准、摆放、版本、是否批准）
  versions/v<N>.json   每改一版，旧版存一份，可退回
  sample/input.md      用户给的样例原料，试跑用
  trials/<时间>/       每次试跑的记录和产出
  proposals/<时间>/    AI 提的改动，等用户点头
  items/<编号>/        一件活一个文件夹
    status.json        这件活的状态，唯一真相
    <各站的产出文件>    当前版本
    tries/<站>/<第几次>.md   每一次尝试的产出，都留着
    feedback/<站>.md    退回理由，下一次重做时交给工人
    run.log            执行器的输出
```

## line.json

```json
{
  "id": "article-summary", "name": "文章摘要线",
  "input": "一篇中文文章", "output": "一段 60 到 120 字的摘要",
  "retire": "这是试验用的玩具线，试验做完就整条删掉",
  "worker": "claude", "model": "haiku",
  "version": 1, "approved_version": null, "approved_at": null,
  "changed_by": "AI", "changed_at": "2026-11-14 22:29",
  "trial": null,
  "flow": ["in", "extract", "summarize", "gate", "review", "out"],
  "nodes": [
    {"id": "in", "kind": "source", "title": "一篇文章", "file": "00-input.md"},
    {"id": "extract", "kind": "station", "title": "提要点", "input": "00-input.md", "output": "10-points.md", "spec": "…", "timeout": 300},
    {"id": "gate", "kind": "gate", "judge": "machine", "title": "字数和格式", "file": "20-summary.md",
     "checks": {"min_chars": 60, "max_chars": 120, "single_paragraph": true, "no_preamble": true},
     "on_fail": "summarize", "max_tries": 3},
    {"id": "review", "kind": "gate", "judge": "human", "title": "验收", "file": "20-summary.md",
     "points": "读着通顺、没有编造、愿意直接拿去用。", "on_fail": "summarize"},
    {"id": "out", "kind": "product", "title": "一段摘要", "file": "20-summary.md"}
  ],
  "layout": {"in": [14, 150], "stop": [476, 318]}
}
```

门有三种，看 `judge`：

- `machine`：程序自动查，不花额度。`checks` 里每一项都可以没有：`min_chars`、`max_chars`、`single_paragraph`、`no_preamble`、`must_include`（每件产出都必须原样出现的固定文字，比如小标题）、`keep_backticks_from`（填一个文件名，那个文件里反引号括起来的内容必须原样出现在产出里）。
- `ai`：由另一个 AI 读懂内容来判。字段 `criteria`（合格标准，一行一条）、可选 `reference`（对照哪个文件，默认是 `on_fail` 那一站的输入文件）。用的模型是线上的 `judge_model`。
- `human`：等用户表态。字段 `points`（验收要点）。

`machine` 和 `ai` 都要有 `on_fail` 和 `max_tries`；`human` 只要 `on_fail`。

站可以有 `refs`：除了 `input` 之外还要一并参考的文件名列表。

- `flow` 是主线的顺序，第一个必须是 `source`，最后一个必须是 `product`。第一版只支持一条主线加退回，不支持几站同时干。
- 连线不单独存：`flow` 里相邻两个是往前的线；门的 `on_fail` 是退回线；机器门另有一条到"停线"的线。"停线"节点不在 `nodes` 里，页面固定画出来，编号 `stop`。
- 一个标准只存一处：字数这类要求只写在门的 `checks` 上，执行器把它转成大白话附在工人的任务里，站的 `spec` 不重复写。
- `trial`：`{"version": 2, "at": "…", "runs": 3, "ok": 3, "running": false}`。`ok` 指走到人判门或出货的次数。
- 用户自己"保存"：版本加一，批准状态不变。AI 的改动：先成为 proposal，用户点头才变成新版并算已批准。

## status.json（一件活）

```json
{
  "id": "0012", "name": "第 12 件", "created": "2026-11-14 22:29:40", "line_version": 2,
  "state": "waiting", "at": "review", "why": null, "pid": 1234,
  "nodes": {"extract": {"state": "done", "since": null}, "summarize": {"state": "done"}, "gate": {"state": "pass"}, "review": {"state": "wait"}},
  "walked": ["in>extract", "extract>summarize", "summarize>gate", "gate>summarize", "gate>review"],
  "back": {"gate>summarize": 1},
  "round": {"summarize": 2},
  "tries": {"summarize": [{"n": 1, "chars": 123, "verdict": "不合格：超出 3 字"}, {"n": 2, "chars": 97, "verdict": "合格"}]},
  "judged": {"gate": ["第 1 次：不合格（123 字，超出 3 字）", "第 2 次：合格（97 字）"]},
  "history": [["22:29:41", "提要点", "做完", "用了 2.8 秒"]]
}
```

- 整件活的 `state`：`running` 正在做、`waiting` 等你验收、`stopped` 停线、`done` 已出货、`abandoned` 已放弃、`idle` 停着（只重做了一步）。
- 节点的 `state`：`done` 做完、`pass` 合格、`run` 正在做、`wait` 等你验收、`fail` 不合格、`stopped` 停在这里。没出现的节点就是"没轮到"。
- 停线时另有 `resume_from`：建议从哪个站接着跑（退回目标站，或出错的那一站）。
- `round` 是这一轮里某站已经写了几次，用来和门的 `max_tries` 比；停线后重新开跑、或人工退回时清零。`tries` 不清零，一直累加。

## 执行器怎么跑

`python app/engine.py run --line <线目录> --item <编号> --from <节点> [--only]`

从指定节点开始一段一段往后走，每一步都先写状态再干活：

- 站：把规格、下游机器门的要求、输入文件、退回理由交给一个全新的命令行工人，产出存成文件。出错或超时就停线。
- 机器门和 AI 判的门：检查产出。合格往后走；不合格且没到上限，写退回理由，回到 `on_fail`；到上限就停线。工人干活时会自动看到它后面这些门的标准。
- 人判门：把状态写成"等你验收"，这一段结束。进程退出，不占着等人。
- 成品：记为已出货，结束。
- `--only`：只做起点这一步就停。

用户在页面上验收后，由服务另起一段：合格从下一个节点开始，不合格从 `on_fail` 开始。

设计一条线时用的另外两条命令：

- `python app/engine.py check --line <线目录>`：定义能不能跑，哪里还弱。
- `python app/engine.py trial --line <线目录> --runs 3`：用样例原料试跑。

## 本机服务的接口

只监听 `127.0.0.1`。读用 GET，改用 POST（JSON）。成功返回 `{"ok": true, …}`，失败返回 `{"ok": false, "error": "大白话原因"}`。

| 接口 | 作用 |
|---|---|
| `GET /api/state` | 当前这条线的定义和状态、它的所有活的摘要、所有线的清单（`lines`） |
| `POST /api/lines/switch` `{id}` | 切到另一条线。之后所有接口都作用于它 |
| `GET /api/item/<编号>` | 一件活的全部：状态、每次尝试的原文、各文件内容、经过 |
| `POST /api/item` `{text, title?}` | 投新料。线没批准时拒绝 |
| `POST /api/item/<编号>/decide` `{node, approve, reason?}` | 人判门表态。不合格必须带理由 |
| `POST /api/item/<编号>/run` `{from, only}` | 从某一步重做。`only` 为真只做这一步 |
| `POST /api/item/<编号>/abandon` | 放弃这件活，文件保留 |
| `POST /api/line/node` `{id, patch, trial?}` | 改某个节点的规格或标准，存成新版。`trial` 为真则保存后试跑 |
| `POST /api/line/layout` `{layout}` | 存节点摆放位置，不算新版 |
| `POST /api/line/approve`、`/unapprove`、`/revert` | 批准、撤回批准、退回上一版 |
| `POST /api/line/trial` `{runs?}` | 用样例原料试跑当前版本 |
| `POST /api/ai` `{scope, text}` | 让 AI 改。`scope` 是 `line` 或节点编号。结果成为 proposal |
| `POST /api/ai/accept`、`/api/ai/reject` | 采用或不要 AI 的改动 |
| `POST /api/open` `{item, file?}` | 用电脑上的默认程序打开文件；不给 `file` 就打开文件夹 |

### GET /api/state 的返回

```json
{
  "line": { "…line.json 的全部字段…": "",
    "proposal": null },
  "items": [{"id": "0012", "name": "第 12 件", "state": "waiting", "state_name": "等你验收", "at": "review", "created": "…"}],
  "now": "2026-11-14 22:50:01"
}
```

`proposal` 有值时：`{"id": "…", "state": "working|ready|failed", "scope": "line", "text": "用户的意见", "summary": ["改了什么，一条一句"], "trial": {"runs": 3, "ok": 3}, "error": null}`。

### GET /api/item/<编号> 的返回

status.json 的全部字段，另加：

```json
{
  "state_name": "等你验收",
  "nodes": {"summarize": {"state": "run", "seconds": 40}},
  "tries": {"summarize": [{"n": 1, "chars": 123, "verdict": "不合格：超出 3 字", "text": "这一次的原文"}]},
  "files": {"00-input.md": "…", "10-points.md": "…", "20-summary.md": "…"},
  "folder": "C:\\ai_workflow\\lines\\article-summary\\items\\0012"
}
```

正在做的节点带 `seconds`（已经做了多少秒）。

### 几处细节

- `POST /api/item` 成功时返回新这件活的编号 `{"ok": true, "id": "0003"}`。活可以带一个名字 `title`，在 `items[]` 和 status 里都有。
- `line.trial` 里可能有 `error`（比如没有样例原料）。只有试跑的版本等于当前版本时才返回，否则是 `null`。
- `POST /api/line/revert {to}`：把第 `to` 版的内容换回来，成为新的一版（版本号加一，历史不改写）。
- 每一个新版本都从草稿开始，要重新批准才能投料。只有一个例外：用户点"采用"的 AI 改动，采用即算批准。
- `POST /api/line/approve`：这一版没试跑过、试跑没全走通、或有站后面没有门时，返回 `{"ok": false, "need_force": true, "concerns": ["…"]}`；页面把这几条列给用户确认后，带 `{"force": true}` 再发一次。`/api/ai/accept` 在 AI 改完试跑没全走通时同理。
- AI 改动待定（`working` 或 `ready`）时，`/api/line/node` 和 `/api/line/revert` 会被拒绝，免得两边的改动互相冲掉。采用时还会核对 AI 是照哪一版改的（`base_version`）。
- `GET /api/state` 的 `line` 里另有：`history`（版本清单，最新在前，每项 `{version, by, at, note, current}`）、`warnings`（例如"「提要点」后面还没有门"）、`worker_name`（工人的显示名）。
- `line.trial.items` 和 `line.proposal.trial.items`：每一次试跑 `{id, name, state, state_name, why}`。`GET /api/trial/item/<id>` 和 `GET /api/proposal/item/<id>` 返回那一次的全部细节，形状同 `/api/item/<id>`，多一个 `readonly: true`。`proposal.line`（`ready` 时才有）是 AI 改后的整条线定义。
- **样例**：`lines/<线>/sample/` 里每个 `.md` 是一份样例原料。`line.samples` 是 `[{name, chars}]`。`POST /api/line/sample {name?, text}` 加一份，`POST /api/line/sample/remove {name}` 删一份（至少留一份），`POST /api/item/<编号>/sample` 把一件正式的活的原料加进样例。
- **试跑**把每份样例各跑若干次。`line.trial.runs` 是总次数，`line.trial.samples` 是 `[{name, runs, ok}]`，`trial.items[]` 每项带 `sample`、`back`（中途被退回几次）和大白话的 `state_name`。`POST /api/line/trial {runs?}` 里的 `runs` 是每份样例跑几次。
- **草稿不干正式的活**：线是草稿时，`/api/item/<编号>/run` 和人判门的"不合格退回"会被拒绝；最后一道人判门的"合格，出货"不受限。一段活按它开始时的规矩跑完，中途改规矩不影响它。
- `POST /api/ai/accept` 只批准 AI 这一次的改动：采用前线是已批准的，采用后仍算已批准；采用前是草稿，采用后还是草稿。返回 `{approved, version}`。
- 站可以有 `model`（这一站单独用的模型）。AI 判的门的 `reference` 可以是一个文件名或一个列表。尝试记录 `tries[]` 每项有 `round`（它在这一轮里是第几次）。
- `lines[]` 每项另有 `running`（正在做的件数）和 `proposal_ready`（有 AI 改动等点头）。
- 试跑和 AI 改线都是独立进程。进程死了，页面会如实显示"中途断了"，不会一直卡在"正在……"。
- AI 改线只有一次点头：改完连同"改了什么"和试跑结果一起给用户看，采用或不要。没有"先说打算、点头后才动手"的中间一步。
- AI 正在改超过 15 分钟没有结果，这次改动自动作废（进程多半已经死了），关掉后可以重新提。
- 页面和服务之间断开时，页面顶部会提示，服务恢复后自动接上。

## 怎么启动和测试

- 启动：双击项目根目录的 `start-canvas.cmd`。它管 `lines/` 下所有的线（名字以 `_` 开头的文件夹不算），页面上可以切换，默认打开上次看的那条。地址 http://127.0.0.1:8765/ 。
- 改了页面代码后要重新构建：在 `app/web` 里运行 `npm install`（第一次）和 `npm run build`。
- 接口测试（用固定输出的替身工人，不花模型额度）：先把一条线复制成 `lines/_test-stub` 并把 `worker` 改成 `stub`，用 `python app/server.py --line lines/_test-stub --port 8766` 启动，再运行 `python app/tests/api_test.py 8766 lines/_test-stub/sample/input.md`。52 项全过才算好。测试线必须是全新的（草稿、没有活），每次测之前重新复制。

## 第一版没做的

几站同时干；拖线改走向、增删站（第二版）；出货后撤销；原料或成品不是一段文字的线；需要工人动本机文件或跑命令的站。
