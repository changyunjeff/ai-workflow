# Troubleshooting slow queries

If a dashboard takes more than a few seconds to load, the cause is almost always a query that scans too many rows.

Start by opening the query log and sorting by duration. Queries that run longer than the `slow_query_threshold` setting (2 seconds by default) are flagged automatically.

A full table scan is the most common culprit. It happens when the filter column has no index, or when the query wraps the column in a function so the index cannot be used. For example, filtering on `DATE(created_at)` prevents the planner from using an index on `created_at`; filter on a time range instead.

Adding an index is not free. Each index slows down writes and takes disk space, so do not index a column just because it appears in one slow query. Prefer a composite index when several queries filter on the same pair of columns.

If the query is already using the right index and is still slow, the result set is probably too large. Add a `LIMIT`, or aggregate the data ahead of time in a materialized view that refreshes on a schedule.
